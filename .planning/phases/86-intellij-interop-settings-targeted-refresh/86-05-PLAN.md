<objective>
Close UAT gap G-86-1: Refresh Java Classes must run without the log filling with
`JsonRpcException: java.io.IOException: Stream closed`. The diagnosed cause is two pre-existing
defects (Phase 1.x and Phase 79, not introduced by Phase 86) that together guarantee two
overlapping stop/start cycles on every deliberate restart, which is exactly the condition that
reaches the known upstream LSP4IJ race where a message queued on the wrapper's single-thread
`messageWriter` is flushed into a process a concurrent stop already destroyed.

This plan removes the self-inflicted trigger in three moves: classify a deliberate stop as
expected so the crash heuristic stops firing a redundant restart; reject a restart request that
lands while a restart is already executing; and make one restart's stop finish before its start
begins.

Purpose: this is the phase's blocker gap. Success criterion 2 of the roadmap ("Refresh Java
Classes does not interrupt diagnostics, completion, hover or Structure View") was observed to hold
visually while the log recorded a broken JSON-RPC stream, so the phase cannot close on the visible
behaviour alone. The defect is not in the new refresh path (D-13 keeps success restart-free), but
the refresh feature's own user-clicked failure fallback (D-14) is one of the deliberate restarts
this fix covers, and the phase's UAT is what surfaced it.

Output: two new platform-free seams and their tests, an in-flight guard on the existing restart
gate, the rewired `BbjServerService` restart path, and extended source guards.
</objective>
