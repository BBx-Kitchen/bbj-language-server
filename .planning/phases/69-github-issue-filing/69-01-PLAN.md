<phase_conventions>
These conventions bind every plan in Phase 69 (`69-01` … `69-13`). This plan establishes them; later
plans cite this block by reference and do not restate it.

**Never `cat` `MAJOR-REFACTORS.md`.** It is 3,465 lines / 578 KB (~145k tokens). Extract exactly one
record block with:

    awk -v ID=<FINDING-ID> '$0 ~ "^id: +"ID"$"{f=1} f{print} f&&/^```$/{exit}' .planning/reviews/MAJOR-REFACTORS.md

Extract the filing-order Index once with `sed -n '107,255p'`. Extract a contiguous band of record
blocks by looping the awk above over the band's finding IDs — never by reading a line range that
spans records you do not own.

**The corpus is closed at 144 and nothing re-triages it.** `proposed_approach:`, `failure_scenario:`,
`proposed_labels:`, `severity:`, `effort:` and `dimension:` are transcribed as written. If drafting
surfaces something the sweeps missed it is a discrepancy for the close-out, not a 145th record.

**Labels come only from `proposed_labels:`** (D-09). Split on `;`, strip the `area=` prefix from the
first part, and use all three values verbatim. `effort:` and `severity:` are never a label source —
`P63-D3-005`, `P66-D2-002` and `P66-D4-001` carry prose inside `effort:` and would produce malformed
calls. All twelve label values already exist in the repository; this phase creates none.

**Titles are `<area>: <problem>`** (D-10), where `<area>` is the bare area label. The finding ID lives
in the body, never in the title. Titles are derived once, in the shard that renders the record, and are
deterministic — the filing run's resume check matches on them (D-14).

**The route predicate** (D-01/D-02), decidable from two fields with no judgement: a record routes to a
private draft security advisory **iff** `dimension: D1` **and** `severity:` is `critical` or `high`.
Everything else routes to a public issue. Over the corpus this selects exactly nine records, all inside
filing-order rows 1-17, and leaves all 24 `medium`/`low` D1-primary records public (D-03).

**Body blocks are delimited** so the filing run can slice one body out without reading the file:
`<!-- BODY-BEGIN <finding_id> -->` on its own line, the body, `<!-- BODY-END <finding_id> -->` on its
own line. Nothing between those two markers may be meta-commentary about the drafting process — the
region between them is the literal bytes that become the tracker body.

**Fixed body section order**, identical for all 144 (ISSUE-02 element ↔ section):

1. `## Problem` — one to three sentences, authored from `evidence:`, naming what is wrong and where.
2. `## Evidence` — the `location:` value verbatim in backticks, then the surface, problem class and
   impact drawn from `evidence:`.
3. `## Failure scenario` — `failure_scenario:` **verbatim** (D-11).
4. `## Proposed approach` — `proposed_approach:` **verbatim** (D-11).
5. `## Acceptance criteria` — authored per D-12: state the observable condition under which the
   failure scenario no longer occurs, plus whatever regression coverage the proposed approach implies.
   No new scope, no design, no implementation commitment.
6. `## Traceability` — one line naming the finding ID, dimension, severity and effort; plus, for a
   record whose `dedup:` is not `none`, one line stating what this finding adds beyond the named
   existing issue (D-08).

**Bodies are self-contained** (D-11): no path into `.planning/`, no pointer to `MAJOR-REFACTORS.md` or
any `6N-COVERAGE.md`, no `§` section reference. Where a verbatim-lifted sentence contains a
review-internal reference (`RU-nn-nn`, an `INVENTORY.md` or COVERAGE-file name, or a `§` pointer), the
sentence is still lifted verbatim and a bracketed gloss is appended immediately after it naming the
referenced thing in terms an outside reader can use — for example `[RU-61-05 is the extension-host
settings layer: bbj-ws-manager.ts and main.ts]`. Seventeen records need this: `P64-D6-008`,
`P63-D1-007`, `P64-D1-002`, `P61-D1-004`, `P64-D3-002`, `P64-D6-005`, `P62-D5-002`, `P63-D5-001`,
`P63-D6-002`, `P64-D6-010`, `P63-D3-006`, `P63-D4-008`, `P62-D1-005`, `P62-D5-003`, `P63-D7-003`,
`P63-D7-006` and `P63-D7-002`. Deleting the reference and leaving it dangling are both wrong.

**No tracker write before the `69-08` approval gate.** Reading the tracker is permitted throughout.
`gh issue list`, `gh label list`, `gh api` GET and `gh auth status` are reads. Anything that creates,
edits, comments, closes or labels is a write and belongs only to `69-09`, `69-10` and `69-11`.

**`derive-review-docs.mjs` is never invoked by this phase and `--force` is never passed** (D-16). It
overwrites `MAJOR-REFACTORS.md` wholesale with always-empty `issue:` fields. The `69-12` write-back is
a targeted edit of 144 `issue:` lines and nothing else.

**Commit subject shape:** `docs(69): <what changed>`, matching Phase 68's convention.

**Phase-local decision IDs.** `D-01`..`D-17` mean `69-CONTEXT.md`'s decisions. A reference to another
phase's decision is always written in full as "Phase 6N D-nn".

**`bc` is not installed.** Arithmetic in shell steps uses `node -e`, `awk` or shell built-ins.
