## Shared Patterns

### Shell-free process launch
**Source:** `bbj-vscode/src/Commands/process-args.ts` (`Argv = {file, args}`, one element per value) via `runProcess` (confines the BBj executable); `BbjRunActionBase.java:440` (`GeneralCommandLine(String, String...)`).
**Apply to:** both decompile flows. Never build a command string; the `-d` value is built from a `mkdtemp` path, never user input.

### Hardened file access (#585)
**Source:** `decompile-io.ts:26-53`.
**Apply to:** open prompt, both decompile commands, Denumber guard (realpath, then lstat, O_NOFOLLOW/O_NONBLOCK where defined, fstat, magic read, always close).

### Judge bbjlst by its output file
Exit code is 0 on failure on BBj 26.03. Require the output file, non-empty, no longer starting with the magic; include bbjlst's captured stdout/stderr in the error text. Applies to both IDEs.

### Deps injection, no `vscode` import outside the host layer
**Source:** `denumber-command.ts` (`DenumberCommandDeps`), `settings-migration.ts` (`SettingsMigrationDeps`). Apply to the new probe consumers and the migration listener logic.

### Plain-English messages
Style of `notTokenizedMessage` and `denumberFailedMessage`: quote the file's basename, name the real cause, no jargon.

### Source and test comment hygiene
No planning IDs in comments; issue numbers fine. Grep the diff before closing the phase.
