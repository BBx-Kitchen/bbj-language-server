# Phase 130.1 Plan 02: One tokenized probe for prompt, decompile and Denumber Summary

**A single realpath-based, #585-hardened `probeTokenizedFile` with a discriminated result now drives the open prompt, both decompile commands and Denumber, so symlinked tokenized programs decompile at their target, FIFOs never block, I/O errors name their cause, and Denumber on a binary program points to Decompile.**

## Performance

- **Duration:** about 12 min
- **Started:** 2026-10-05T07:56:00Z
- **Completed:** 2026-10-05T08:08:00Z
- **Tasks:** 3
- **Files modified:** 10

## Accomplishments

- `probeTokenizedFile` in `decompile-io.ts` resolves symlinks with `realpath`, then applies lstat, `O_NOFOLLOW`/`O_NONBLOCK` and an fstat re-check to the resolved path, and returns `tokenized`, `not-tokenized`, `not-a-file`, `missing` or `unreadable` (with code and one-line message). `isTokenizedFile` is a wrapper.
- The open prompt lost its own symlink-following, FIFO-blocking `readLeadingBytes` and uses the probe; an unreadable file is one BBj-channel line (`Could not check whether "<name>" is a tokenized BBj program: <cause>`), no popup, and the reservation key is released so a later event probes again.
- `decompileReplace` and `decompileReadonly` hand bbjlst and the in-place replace the resolved path while still opening the path the user opened, so a link keeps its own tab. A real-bbjlst case proves target rewritten, link still a link, folder holds exactly the two entries, no private directory left.
- Each refusal names its real cause: `Could not read "<name>": <cause>` (error), `"<name>" was not found, ...`, `"<name>" is not a regular file, ...`, and the unchanged not-tokenized warning; all before any temp directory or bbjlst launch.
- Denumber checks the target first and, for a tokenized program, shows `"prog.bbj" is a tokenized (binary) BBj program. Use "Decompile Tokenized BBj Program" first.` without opening, showing or sending anything.

## Decisions Made

- Kept `isTokenizedFile` as a wrapper because plan 01's `verifyListing` uses it on the private listing; `statSize` stays lstat-based and runs first, so a planted symlink at the listing path is still treated as absent.
- ENOENT after a successful `realpath` (a file removed between the two steps) is reported as `missing`; every other open/read error is `unreadable` with its code, including `ELOOP` from a post-resolution symlink swap.
- A rejected Denumber probe is treated as not tokenized, so the Denumber flow reports its own errors in its own words.
