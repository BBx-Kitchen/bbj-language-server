# Phase 130.1 Plan 06: Settings migration after activation Summary

**The splitSingleLineIF -> splitSingleLineIf migration now re-runs from a single-flight, key-filtered onDidChangeConfiguration listener with a fresh configuration per run, and cleans up a half-done move where both keys already hold the same boolean.**

## Performance

- **Duration:** 12 min
- **Completed:** 2026-10-05T06:59:23Z
- **Tasks:** 2 (3 commits: one tracer, one RED, one GREEN)
- **Files modified:** 5

## Accomplishments

- A late old-spelling value (Settings Sync pull, hand edit, workspace settings change) is migrated without a window reload. `startFormatterSettingsMigration(context)` runs the migration once on activation, then registers `onDidChangeConfiguration` filtered with `affectsConfiguration('bbj.formatter.splitSingleLineIF')`.
- `createSingleFlightRunner` (new export, still no `vscode` import) guarantees no two migrations overlap; events arriving during a run cause exactly one more run. Each run reads `vscode.workspace.getConfiguration('bbj.formatter')` and `vscode.workspace.isTrusted` afresh.
- `migrateScope` now returns `'moved' | 'cleaned' | 'none'`. An equal old/new pair removes only the old key and logs `Removed bbj.formatter.splitSingleLineIF from the <scopes> settings; bbj.formatter.splitSingleLineIf already holds the same value.`; differing values are left alone silently; a failed removal logs `Could not remove ...` and still resolves.
- The server-side fallback (`bbj-format-settings.ts` and its test) is byte-identical to the phase base.

## Decisions Made

- The activation run uses the same runner as event runs, so the two cannot overlap; this also keeps the activation-time `getConfiguration` failure inside the runner's catch, so a host without these APIs still activates.
- Differing old/new values are deliberately silent: the new key already wins in the language server, and logging would repeat on every unrelated settings event for that key.
- No change for IntelliJ or the server fallback (research Answer 4: IntelliJ sends only `splitSingleLineIf`).
