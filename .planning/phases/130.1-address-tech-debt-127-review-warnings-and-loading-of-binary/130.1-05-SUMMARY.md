# Phase 130.1 Plan 05: Versioned denum diagnostics Summary

**bbj/denumDiagnostics now carries the document version it was computed for, stamped from the server's own document mirror after an applied edit, and VS Code places problems only on an exact version match.**

- **Completed:** 2026-10-05T07:14:00Z

- **Files modified:** 10

## Accomplishments
- `DenumDiagnosticsParams.version?: number`; the no-edit path stamps the live version and the key is left out entirely when the version is unknown.
- `mirrorVersionFor` waits (bounded by `DENUM_VERSION_WAIT_MS`, 5 s) on `TextDocuments.onDidChangeContent` until the mirror holds the denumbered text and stamps that mirror version; it never rejects and always releases the subscription and timer.
- `denumPayloadVersion` (safe non-negative integer or undefined) and a version guard in `placeProblems`; the log block is written first as before, so the log copy always exists.
- Tests: new behaviour cases for one-change, two-change, late-change, never-change, text-mismatch and the bound itself; placement refusing missing, invalid, older and newer versions; the validator's accepted and rejected values.

## Decisions Made
- Only runs that send a list wait for the mirror. A clean denumbered run sends no notification, so waiting there would only add latency (and 5 s timeouts in suites whose fakes never deliver the change).
- The mirror comparison is exact text equality, so a client that rewrites line endings gets a log-only list rather than problems on possibly shifted lines.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Two suites outside the plan's file list needed editor-like fakes**
- **Found during:** Task 2 (verification run)
- **Issue:** `denum-command.test.ts` builds its own harness whose `workspace.applyEdit` accepts an edit without touching the fake client document, so runs with diagnostics waited out the 5 s bound and hit vitest's default timeout. `bbj-denum-service.test.ts` had a test ("the same successful run twice on an unchanged document") that assumed the document stayed numbered after an accepted edit, which the editor-like shared harness no longer does.
- **Fix:** `denum-command.test.ts` now applies accepted edits to its fake client document via the shared `applyEditsAsClient`; the repeated-run test puts the numbered text back and rescripts the answer between the two runs and is renamed "the same successful run twice shows two messages". Both follow the plan's own acceptance criterion that every fake resolving an applied edit for a run with diagnostics also updates the fake client document.
- **Files modified:** `bbj-vscode/test/denum-command.test.ts`, `bbj-vscode/test/bbj-denum-service.test.ts`
- **Verification:** `npx vitest run` over the five denum suites: 208 passed

- **Files modified:** `bbj-vscode/src/language/bbj-denum-service.ts`
- **Verification:** outcomes and service suites pass; clean-run test unchanged
