87-PATTERNS.md shows the action's availability check as
`BbjConfigPathService.getInstance(project).isConfigFile(file)`. That is wrong: the real accessor takes
no argument (`public static BbjConfigPathService getInstance()` at `BbjConfigPathService.java:34`).
Use `BbjConfigPathService.getInstance().isConfigFile(file)`. Code wins over the pattern map.

D-01 and D-03 also need reconciling, and the reconciliation is locked here: D-01 requires the
availability decision to be PSI-free, and D-03 requires the action to be available on **every** line
of a config file. So `update()` gates on file scope only — it never inspects the caret line's text.
The line-text decision (edit an existing SETOPTS line versus compose a new one) happens at launch,
through the `bbj/composer/setopts/decodeCall` request, which keeps the parsing in
`setopts-catalog.ts` where it belongs and satisfies D-01's "no PSI" constraint everywhere.
