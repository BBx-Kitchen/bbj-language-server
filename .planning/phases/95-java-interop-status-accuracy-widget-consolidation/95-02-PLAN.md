<objective>
Stop the java-interop poll from probing every 5 seconds for the life of the project. Gate the
re-arm on whether a BBj file is currently selected (D-06), freeze and stay silent while paused
(D-07), fire an immediate check when the gate opens (D-08), and put the dead `CHECKING` constant to
work for the probe's real in-flight duration (D-09) — all with the gate decision extracted into a
`com.intellij`-free class under plain JUnit (D-10).

Purpose: ROADMAP criterion 2. D-08 also closes a bug that exists today independently of the gate:
`startChecking()` calls `scheduleNextCheck()`, which schedules even the **first** check 5s out, so
the status bar shows an initial or stale value for five seconds after every server start.

Window focus is deliberately not used, though #593 offers it: the plugin uses no focus or activation
API anywhere in `src/main/java` today, so focus gating would add a brand-new platform coupling and a
second event source that can race with editor selection (D-06). The accepted cost is that an IDE
left open on a BBj file overnight still polls.

Output: one new platform-free policy class, a gated and CHECKING-aware `BbjJavaInteropService`, and
two new test classes.
</objective>
