<objective>
Make the java-interop status true: replace `checkConnection()`'s bare TCP handshake with a real
LSP4J JSON-RPC round-trip that requires a valid `getTopLevelPackages` result (D-01, D-02), bound it
with a split timeout budget (D-03), give a squatting peer its own user-visible state and banner
sentence (D-04, D-05), and guard both disposal-unsafe sites in the same file (D-17).

Purpose: ROADMAP criterion 3 — "a foreign process squatting on the configured port does not produce
a Connected status" — is currently false, and the maintainer's own machine reproduces it (BBjServices
holds port 5008 without speaking the interop protocol). This criterion deliberately **overrides
#587's own acceptance criteria**, which asked only that the limitation be documented. Close #587
recording that its acceptance criteria were too narrow, not met as written.

IOP-01 rides in this plan rather than a later one because D-01 and D-03 widen the in-flight window
from a ~1s connect to a ~3s connect-plus-request, which makes the disposal guard more necessary than
when #592 was filed (D-17) — and `checkConnection()` is the single method both changes edit.

Output: a new `com.basis.bbj.intellij.interop` package holding three platform-free classes, a
rewritten `checkConnection()`, a fourth `InteropStatus` constant, reason-varying widget and banner
text, and three new test classes.
</objective>
