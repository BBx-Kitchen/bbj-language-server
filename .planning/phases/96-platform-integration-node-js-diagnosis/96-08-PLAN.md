<objective>
Close UAT gap G-96-2: a too-old configured Node.js is rejected, but the user is never led to a
working runtime. Two independent causes, both required for the gap to fail, both small.

The language server's start-failure notification builds a single hardcoded configure-path action and
receives only a message string, so the `NodePresentation` seam built in plan 96-05 and wired into the
editor banner in 96-06 never reaches it. And the Settings dialog's "Version too old" statement says
nothing about the recovery the resolver already supports: clearing the field.

Purpose: the too-old-Node state stops being a dead end. The notification offers the download the
resolver's own rejection reason already authorises (D-08), the three Node.js surfaces finally agree
on what to OFFER and not only on the verdict (D-06), and the dialog names the recovery at the exact
spot the tester pointed at.

Output: one new shared action mapping, two rewired surfaces, two settings copy changes, three new
test files, a distributable built from the final tree, and a human re-UAT of Test 2 on Windows.

Shape notes, so the deviations are deliberate rather than accidental:
- No `tracer` task. This phase's architecture is already proven and shipped -- the reason-driven seam
  and its first consumer landed in 96-05 and 96-06 with tests. Task 1 is itself the end-to-end slice
  (resolver rejection to rendered action) for the second consumer; a thinner slice would add no
  information.
- Four tasks rather than the usual two-to-three. Tasks 1 and 2 are the two fix sites; Task 3 is the
  build gate and Task 4 the human attestation, which exist only because this gap can be closed on no
  machine in this environment. Neither writes product code. Splitting them into a second plan was
  rejected: the maintainer asked for one lean plan, and the build must come from the tree that
  carries both fixes.
</objective>
