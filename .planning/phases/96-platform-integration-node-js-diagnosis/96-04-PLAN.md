<objective>
Consolidate four editor notification providers onto one base. #622 names three; there are four
registered (`plugin.xml:254-265`), and the fourth is the one carrying the bug: the server-crash
provider guards by file **extension** against `bbj|bbl|bbjt|src`, while the BBj file type is
registered for `bbj;bbjt;src;bbx`. It therefore fires on `.bbl` files, which carry no BBj file type,
and misses genuine `.bbx` programs. `BbjFileVisibility`'s own javadoc already diagnoses exactly this
mistake.

Purpose: ROADMAP criterion 3 asks that the providers share one base carrying the file-type guard and
panel construction. D-09 deliberately **overrides** that criterion's second half — "each banner still
appears and disappears in exactly the conditions it did before" — because preserving the crash
provider's conditions means shipping the `.bbl`/`.bbx` bug into 0.16.0 and keeping two contradictory
file-guard conventions in the tree. This mirrors Phase 95's D-01, which overrode #587's own
acceptance criteria with recorded reasoning.

This plan lands the base BEFORE the sibling plan that rewrites the missing-Node banner's decision
call, per the ROADMAP ordering note, so the banner change is written into the shared shape once
rather than twice.

Output: a new abstract base, four thin subclasses, one widened predicate, a new source guard for the
base, and a re-pointed marker in the guard that the sibling banner plan will later rewrite entirely.
</objective>
