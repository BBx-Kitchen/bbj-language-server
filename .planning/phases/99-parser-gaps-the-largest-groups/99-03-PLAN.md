<objective>
Make the word `label` usable as a name in every position the group shows — a label declaration alone
or in front of a statement, a `GOTO`/`GOSUB` target, and a plain variable — about 25 files, while the
library grammar keeps the same word as its own keyword.

Purpose: the word is declared lowercase in the grammar, for the library's symbolic-label declaration.
The token builder's generic loop only hands the identifier category to keywords whose declared text
contains an uppercase run, so this one word is silently excluded and cannot satisfy any name position
at all — the whole file fails to parse, not just the one statement. This codebase already shipped the
fix once for another lowercase-declared keyword by listing the literal as an explicit alternative in
the rule that needs it; this plan applies the same pattern (D-04). Only this word is tested and
claimed; any other word that starts working is recorded, not claimed (D-05).

Output: the widened feature-name rule, a new narrow label-name rule used by the label declaration and
the user-label cross-reference, the regenerated parser, the fixture `label-word-as-name.bbj`, new
cases in `parser-keyword-statements.test.ts`, and this group's measurement section in
`99-CONFORMANCE.md`.
</objective>
