<objective>
Unfuse the `LEN=` keyword literal so the `RECORD` verbs' `LEN=` channel option parses, the INPUT
verifier's own `LEN=a,b` form keeps parsing, and `LEN` becomes usable as an ordinary variable name.

This plan is the phase tracer: one thin path wired end-to-end through every layer this phase
touches — grammar rule -> `langium:generate` -> regenerated parser -> conformance fixture -> live
test assertion -> private conformance measurement — proven green before any other construct is
attempted. The three later grammar plans each drop their own rule and fixture into the loop this
plan proves.

Purpose: the grammar declares a single fused 5-character literal `'LEN='` inside `LastVerifyOption`.
Langium's keyword vocabulary is global to the whole grammar, so the lexer emits that token wherever
those four characters appear — including inside the unrelated `Option` rule that the `RECORD` verbs'
channel options use, whose own required `'='` is then stranded ("Expecting token of type '='").
It is the second-largest list-A group (38 files) and the smallest change in the phase (D-01, D-02).

Output: the split `'LEN' '='` in `LastVerifyOption`, the regenerated parser, the fixture
`record-verbs-len-option.bbj`, a new parser test file carrying the positive, still-flagged and
keyword-as-identifier cases, and `99-CONFORMANCE.md` with this plan's measurement.
</objective>
