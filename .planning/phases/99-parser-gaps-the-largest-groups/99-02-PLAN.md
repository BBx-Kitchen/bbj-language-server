<objective>
Add a `FieldStatement` grammar rule so `FIELD` used as a verb parses — the single largest list-A
group, 45 files — while the class-member `FIELD` declaration stays exactly as it is.

Purpose: no grammar alternative claims the verb form today. The keyword is already in the identifier
category, so it is consumed as a bare expression statement and the parser then has nowhere to put the
following comma. The fix is one new alternative in the `SingleStatement` alternation whose three
parts are plain expressions (D-08); the class-member declaration is reachable only through the
class-member alternation, so the two never compete (D-09).

The load-bearing detail is the name part: the expression grammar's relational level takes the equals
sign as a comparison operator, so a name part written at the full-expression level makes the parser
consume `name$=dec(x$)` as one comparison and then fail looking for the statement's own equals sign.
The name part must be parsed below the relational level — this is the first thing the post-edit probe
has to confirm.

Output: the `FieldStatement` rule and its alternation entry, the regenerated parser, the fixture
`field-verb.bbj`, new cases in `parser-keyword-statements.test.ts`, and this group's measurement
section in `99-CONFORMANCE.md`.
</objective>
