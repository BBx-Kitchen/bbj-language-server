<settled_facts>
Research is disabled for this project; these were settled by reading the checked-in sources and are not open questions.

- **`ComposerRequestContractTest` cannot host the new name.** Its `DECLARED_REQUESTS` set is asserted equal to the names reflectively derived from `BbjComposerServer`'s `@JsonRequest` methods (`theDeclaredRequestNamesAreDerivedFromTheInterfaceNotHardCodedTwice`). Adding a client-side `@JsonNotification` name to that set would fail that very test. The reload notification therefore needs its own cross-language contract test, which this plan creates. `bbj/resolvedConfigPath` appears in `DECLARED_REQUESTS` only because it doubles as a `@JsonRequest` on the proxy interface; the reload notification is a pure notification and must not be added there.
- **`BbjServerService.RESTART_DEBOUNCE_MS` is `private static final int` (line 42)** and is used only by `scheduleRestart()`. D-11 names it explicitly as the delay the handler passes, so this plan widens its visibility to `public` — the minimal change that keeps one constant rather than duplicating the literal 500 at a second call site.
- **`BbjStatusBarWidget` sets no tooltip today.** `updateStatus(ServerStatus)` computes an icon and a text and assigns them inside `invokeLater`; the panel has a mouse listener but no `setToolTipText` call. The reason therefore attaches as a new tooltip on the existing panel rather than by changing the widget's text, which keeps the widget's five status labels stable.
- **The crash/auto-restart branch in `BbjServerService.updateStatus`** already distinguishes "first crash, auto-restarting" (`crashCount == 1`) from "crashed twice, stopping auto-restart" (`crashCount >= 2`, which raises the existing crash balloon). The reload reason must survive the first case (the restart is still in progress) and clear in the second.
</settled_facts>
