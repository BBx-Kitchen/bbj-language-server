**The enumerated-line grammar**, frozen by `65-01` and used unchanged here:

```
- [SEC-04][<stage>] <site path> — <verdict> — <written line>
- [SEC-04][<stage>] <site path> — pending
```

`<stage>` is exactly one of `acquisition`, `at-rest`, `exposure`, `expiry`. `<verdict>` is exactly
one of `pass`, `fail`, `undetermined`, `n/a`. A `fail` names the finding ID that discharges it — a
new `P65-D1-nnn` **or** an inherited `P6{1,2,3,4}-D1-nnn` owner from the ledger, which is D-04
rendered as a grep. An `undetermined` names its `### Not-reproducible dispositions` entry. An `n/a`
carries a written reason. The section holds four lines per enumerated site: one per stage, no gaps.

**Task split.** Task 1 takes the two stages that concern where the secret comes from and where it
sits; Task 2 takes the two that concern where it leaks and when it stops being valid — and closes
the surface. The split is by stage rather than by module deliberately: a stage answered at only one
IDE is the failure mode this surface exists to prevent, and a task that owns a stage across every
site cannot produce one.
