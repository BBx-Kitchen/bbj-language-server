The open question: **what counts as "a file" for the coverage denominator?** The roadmap and
REQUIREMENTS speak of "every file in scope", but the repository contains four categories whose
status is genuinely ambiguous — machine-generated TypeScript (`bbj-vscode/src/language/generated/`),
binary vendored artifacts (`bbj-vscode/tools/formatter/*.jar`), data catalogs that are not code
(`bbj-vscode/src/language/lib/*.bbl`), and lockfiles (`bbj-vscode/package-lock.json`).

**Planner's working assumption, to be recorded explicitly in the inventory and correctable by the
developer:** a file is in the denominator if it is hand-written and shipped. Generated TypeScript is
excluded (already an explicit Out-of-Scope entry). Binary JARs are **in** the denominator for D1 and
D6 only, because their content cannot be read but their provenance, version and pinning can be
assessed. `.bbl` catalogs are **in** the denominator as data with a narrow applicable dimension set.
`package-lock.json` is **in** the denominator for D6 only, as the dependency-tree source.

Task 1 records this assumption in the document as a stated convention with its rationale. It is a
plan-visible assumption, not a silent decision.
