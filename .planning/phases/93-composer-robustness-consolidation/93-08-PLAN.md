<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| language server → SETOPTS dialogs (`bbj/composer/setopts/*`) | an untrusted-shape response carries the verdict that decides whether OK is clickable |
| SETOPTS dialog OK → `ComposerLauncher` write path | an accepted selection becomes a write into live BBj source |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-93-23 | Tampering | `SetoptsComposerDialog` OK gate | high | mitigate | OK is gated on the server's `valid` verdict instead of enabled unconditionally, so a selection the server considers unwritable can no longer be accepted and written into live source |
| T-93-24 | Tampering | duplicated client-side hex rule | high | mitigate | The Java rule is deleted rather than kept in sync: it had already diverged from the server's check, which had no length bound, and a divergent client rule is what let an invalid tail reach the write path |
| T-93-25 | Tampering | `SetoptsTriStateComposerDialog` OK gate | high | mitigate | The tri-state dialog gates on a fail-closed verdict, so a malformed or partial composeTriState response leaves Apply disabled rather than writing a composition that never arrived |
| T-93-26 | Denial of Service (local) | write-path validation | medium | accept | Deliberately no second gate at `ComposerLauncher`'s write path: it would either re-run a server round trip on or near the EDT inside a write command, which the standing off-EDT convention forbids, or re-implement the rule in Java, which is the duplication this plan deletes. Residual risk is covered by the dialog-side verdict across all six dialogs plus the launcher's existing empty-value guards |
| T-93-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan adds zero packages to `bbj-intellij/build.gradle.kts`; no install task exists, so the package-legitimacy gate has nothing to clear |
</threat_model>
