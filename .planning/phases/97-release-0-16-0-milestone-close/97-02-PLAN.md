<objective>
Fix folded todo 2: `BbjServerService.updateStatus` reads the `previousStatus` field for both the log
line and the classifier argument, but that field is only assigned at the end of the previous call,
so it holds the status from **two** transitions ago. The log is misleading and — more seriously —
`ExpectedStopGuard.classify` is fed a stale from-state on every call.

Purpose: correcting it changes what the classifier actually receives, which 97-CONTEXT.md D-08 makes
a deviation to surface to the maintainer rather than a silent absorption; the todo itself says "do
not change the classifier input without a test that pins the intended behaviour". So the order is
fixed: pin first, ask second, change third.
Output: two executable pins, one maintainer decision record, one corrected call site.

- `BbjServerService.updateStatus` — the corrected classify/log from-state, and the removal of the now-unread stale field.
