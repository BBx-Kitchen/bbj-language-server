<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local branch -> public `origin/main` | Everything pushed becomes permanent public history under the maintainer's repository. |
| PR body -> GitHub issue state machine | A closing keyword in the body silently closes issues at merge time, ahead of any released version. |
| Feature branch -> release version history | `preview.yml` bumps `package.json` on `main` independently; a naive merge can regress it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-97-17 | Information Disclosure | Public commit history | high | mitigate | The register check over added diff lines runs before the push and blocks on any planning identifier; it is re-run after the merge-in of `origin/main`. |
| T-97-18 | Tampering | Release version validator input | medium | mitigate | An equality gate compares the merged `package.json` version line to `origin/main`'s, so a regression fails the task rather than landing. |
| T-97-19 | Repudiation | Issue state | medium | mitigate | A grep over the PR body rejects any GitHub closing keyword, keeping issue closure a deliberate, post-release act. |
| T-97-20 | Tampering | Release workflow definition | high | mitigate | An exit-code diff against `origin/main` asserts both workflow files are byte-identical on the branch that opens the PR. |

No package-manager install occurs in this plan, so the package-legitimacy gate does not apply.
</threat_model>
