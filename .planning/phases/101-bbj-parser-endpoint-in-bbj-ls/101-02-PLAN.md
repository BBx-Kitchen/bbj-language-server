<objective>
Fill the parse in behind the signature plan 01 fixed. BBj's own parser runs over the supplied
text with type checking off (D-05), programs the document references are resolved through the
request's prefixes and workspace roots (D-06, D-07) and read from disk (D-09), a reference that
resolves nowhere becomes BBj's own error rather than something bbj-ls invents (D-08), and the
JSON the parser emits is mapped one-for-one onto the `ParseError` DTO including the multi-value
error-type list (D-03) and BBj's verbatim editor coordinates (D-04).

The load-bearing structural rule of this plan: the `ProgramFactoryIF` and its prefix algorithm are
built ONCE per connection and never per request (D-10). BBj's AST layer keys its shared,
process-wide program cache on the canonical name alone and relies on a long-lived per-instance
tracker to notice a new source UUID; a factory rebuilt per request starts that tracker empty and
can hand back another connection's stale parse. This is settled, not discretionary.

Purpose: turn the tracer's empty result into the compiler's real verdict, with referenced
programs resolved in context.
Output: `BbjPrefixAlgorithm`, `ParserWorker`, a real `parseProgram` body, and seven live-socket
integration scenarios.
</objective>
