<objective>
Make the Node.js download's in-progress check atomic and in-memory, and lock in the already-correct
off-EDT dispatch for Run As BUI/DWC and EM login with a runtime assertion plus a source guard.

Purpose: `downloadNodeAsync` today reads a persisted `PropertiesComponent` boolean and writes it inside
the background task, so the read-then-write is neither atomic nor even ordered before queueing — two
near-simultaneous clicks start two downloads into the same target path — and an IDE killed mid-download
leaves the flag true forever (#537). Separately, #506 is verify-and-close: the off-EDT dispatch landed in
v4.1 (CR-02, commit 06eb1a7) and needs a regression test plus a live tripwire so it cannot silently
regress. D-16 makes this plan 3 of 3; it shares no file with plan 79-02.

Output: a plain-Java `DownloadGuard` beside `BbjNodeDownloader`, the persisted flag deleted, the
assertion added to both #506 paths, and red-then-green JUnit 5 coverage under `./gradlew test`.
</objective>
