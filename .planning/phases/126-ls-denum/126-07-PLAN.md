VS Code facts (planning research, checked against the source of 1.101.0 and main):
- `workbench.actions.view.problems` is the Problems view's open command
  (`contrib/markers/browser/markers.contribution.ts`, `openCommandActionDescriptor`). Its run method
  takes `{ preserveFocus?: boolean }`. With `preserveFocus: true` it always calls
  `openView(id, false)`: it opens the view, keeps the focus where it is, and never toggles the view
  closed (`services/views/browser/viewsService.ts`, registerOpenViewAction). Without the flag it
  takes focus, and it hides the panel when the Problems view already has focus. The engine floor is
  ^1.101.0.
- VS Code fires `onDidChangeTextDocument` with an empty `contentChanges` when only the dirty state
  changes (for example on save).
- The languageclient's default uri conversion is `Uri.toString()`, so the payload uri equals
  `document.uri.toString()` of the open document the server denumbered.

Contract this plan adds (`denum-diagnostics-output.ts`, still free of any import of the vscode module):

```typescript
export const MAX_DENUM_PROBLEMS = 500;
export interface DenumProblem {
    /** Zero-based line in the document, already clamped to it. */
    line: number;
    severity: 'ERROR' | 'WARNING' | 'INFO';
    /** Flattened message plus the parenthesised suffix. */
    message: string;
}
/** The payload's uri when it is a string; otherwise undefined. Never throws. */
export function denumPayloadUri(params: unknown): string | undefined;
/** One problem per valid entry, in payload order, at most MAX_DENUM_PROBLEMS. Never throws; garbage gives []. */
export function denumProblems(params: unknown, lineCount: number): DenumProblem[];
```

Fixed values: collection name `bbj-denum`; Diagnostic source `BBj Denumber`; reveal command
`workbench.actions.view.problems` with `{ preserveFocus: true }`. Message suffixes:
- `syntax error (original line 0010)`: a located entry with an original number
- `note (no location)`: line 0 with no original number
- `note (no location, original line 0010)`: line 0 with an original number
- the message alone: a located entry without an original number
