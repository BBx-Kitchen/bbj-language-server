**Evidence rule for this whole unit (D-12).** GitHub Actions cannot be executed here, so no finding
may claim a workflow was run or was exploited. A `RU-64-01` D1 finding is valid when it names four
things: the **workflow file and line**, the **trigger** that reaches it, the **untrusted input**
that flows in, and the **sink** it reaches. A finding that names a sink without a reachable trigger
is an observation, not a finding — record it as `pass` with a written note saying what was checked
and why it does not reach.

*D1 Security* (tier `repro`, satisfied by trace per D-12). Assess against REQUIREMENTS.md's D1

errors. The concrete checks, run across all six workflows and stated per file where they differ:

action input, with the file and line, since a value interpolated into a shell string is evaluated by
the shell rather than passed as an argument; **(c)** whether any job that handles a secret is
reachable from a fork PR, and what guards exist — `pr-vsix.yml` carries a same-repository condition
on at least one step, so state what it guards and what it does not; **(d)** what each workflow does
