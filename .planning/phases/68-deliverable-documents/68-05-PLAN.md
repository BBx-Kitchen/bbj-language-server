alone in a GitHub issue body two phases from now. This plan writes those 26 honestly: the shape of the
work, its unknowns, and its owner where another unit owns it.

<phase_conventions>
This plan is bound by `68-01-PLAN.md` §`<phase_conventions>`. Read that block before starting.

**Authoring rule for every approach in this plan.** Open the record with the awk extractor, read its
`evidence:`, `failure_scenario:` and `classification:` fields, and write an approach that: names the
concrete files or subsystems the work touches; states what would have to be true for the work to be
finished; and, where the record's own clause records `FAIL`, `n/a` or `moot`, says so and names what
blocks a single-edit answer. Never restate the failure scenario as the approach — the two fields are
read together in a Phase 69 issue body and a duplicate wastes both. Two to five sentences.

**Do not touch any other field.** This plan writes `proposed_approach:` values only.
</phase_conventions>
