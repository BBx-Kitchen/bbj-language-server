- `node_modules/langium/lib/service-registry.js` `getServices(uri)`:
  - looks up `textDocuments?.get(uri)?.languageId` in the language-id map first;
  - then falls back to file name or extension (`langium-config.json` registers `.bbj`, `.bbl`, `.bbjt` only);
  - otherwise throws. `hasServices(uri)` wraps that lookup.
  So a config document named `myconfig.bbj` but opened as `bbx-config` still has services by extension,
  which is why the filter must check the language id first.
- `node_modules/langium/lib/workspace/document-builder.js` `update(changed, deleted, cancelToken)`:
  - sets `currentState = Changed` immediately;
  - for each changed uri without a document, adds an unparsed placeholder;
  - the parse phase later calls `getServices`, which throws for a uri with no services.
  `awaitDocumentState` rejects with ServerCancelled for a uri with no document.

  `LangiumSharedServices`; it overrides `shouldValidate`, `buildDocuments` and `shouldRelink`. It has no
