<objective>
Put the new CVS requests and the MSGBOX compose-and-replace payload on the wire, for IntelliJ to consume
(DISC-02 #648, DISC-03 #649).

The language server gains two thin `bbj/composer/cvs/*` handlers and a `cvs` catalog. IntelliJ gains the
matching DTOs on `ComposerModels`, two methods on the single `BbjComposerServer` interface, `MsgboxReplace`
on the MSGBOX decode result, and equality functions that let the stale-edit guard compare the new shapes.
Everything is pinned by the existing contract, boundary and equality test families (Pitfall 3), which are
extended rather than duplicated.

The request names follow the SETOPTS two-request shape, `decodeCall` + `preview`, per Claude's discretion
and RESEARCH.md Open Question 1.

Purpose: the IntelliJ CVS dialog and the MSGBOX banner (plan 89-08) can be built against a pinned wire contract.
Output: TS handlers with tests; Java DTOs, interface methods, equality functions, and contract/boundary/equality tests.
</objective>
