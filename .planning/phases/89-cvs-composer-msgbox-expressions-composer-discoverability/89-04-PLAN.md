<objective>
Make a composer cue clickable in IntelliJ (DISC-01, #650).

LSP4IJ already renders the language server's `textDocument/codeLens` response as Code Vision entries,
with no plugin code. When clicked, it executes the lens command by looking up an IntelliJ action whose
id equals the command string (verified in the pinned 0.21.0 jar: `CommandExecutor` →
`ActionManager.getAction`, with the command in the data context under `CommandExecutor.LSP_COMMAND`).

This plan adds that action, plus an explicit-position launcher entry, so a click opens the composer for
the cue's own call without relying on the caret (D-06). Stale cues are handled safely.

It is the IntelliJ half of the tracer, and the render/click spike in plan 89-06 depends on it. The
action is wired for every launcher kind that exists today. CVS joins in plan 89-12, once
`ComposerLauncher.Kind.CVS` exists (plan 89-08).

Purpose: DISC-01 clickable cue in IntelliJ, with no Java re-implementation of composer applicability
(D-07's anti-feature guard): the action only routes a server-computed target.
Output: `ComposerLensKinds`, `ComposerLensTarget`, `ComposerLauncher.launchAt`, `BbjOpenComposerAtAction`,
the plugin.xml registration, and allowlist/canary/boundary/source-guard/contract tests.
</objective>
