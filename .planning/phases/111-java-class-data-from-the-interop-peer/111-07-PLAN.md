<objective>
Close UAT gap G-111-2. After Phase 111, Java hover and completion documentation escape every
Markdown link character. BASIS ships a trailing documentation link at the end of each documented
member in the installed javadoc, for example
`\r\r[Docs](https://documentation.basis.cloud/BASISHelp/WebHelp/gridmethods/bbjgrid/scrolling/bbjgrid_ispaging.htm)`.
The escaping turned that link into literal text, and the user asked for it to be a clickable "Docs"
hyperlink again. Raw HTML behaves as intended in both IDEs, so the amended D-06 (leave `<`
unescaped) stands.

This is a user-directed amendment of D-06/D-07, recorded in UAT on 2026-09-27. One narrowly
allowlisted trailing link is exempt from the escape. Everything else stays escaped exactly as
before.

The allowlist was measured at planning time against HEAD `ead3144c` with a scratch probe outside
the repository. The repository was not touched.
- Installed javadoc corpus: 41 files under `/opt/bbx/documentation/javadoc` with 9,473 documented
  entries. 3,907 of them carry the link. Every one has the label `Docs`, the host
  `documentation.basis.cloud` and the scheme `https`, and sits at the very end after `\r\r`. No
  entry has a second link of any kind. The path characters seen are
  `./3ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz`, and the longest URL is 169
  characters.
- With the pattern given in Task 1, all 3,907 real links stay clickable, and all 20 spoof variants
  tried come out fully escaped. Those variants include every row in Task 1's behavior list, plus a
  port, a query, a fragment, an angle-bracket destination and an empty path. A text truncated
  inside the link comes out fully escaped. The slowest corpus entry took 0.55 ms, and a
  35,750-character pathological input took 0.11 ms.

Task 1 is the tracer. It adds the helper and wires it into hover (both the stored and the fallback
path, which share one return statement), with unit tests for the real tail and the spoofs. Task 2
wires completion and records the amendment in 111-CONTEXT.md. One plan is used because the user
wants lean, minimal changes.

Purpose: the only link BASIS itself ships in the javadoc should work again. Link and image syntax
supplied by the peer should still never render (#524).
Output: one exported helper in `java-peer-guard.ts`, two one-line call-site swaps, and 21 new
tests in the existing phase test file.
