<objective>
Stop the "Java class java.io has no container, packageName: java" log line (issue #676) by fixing the
caller that sends a bare package name into class resolution, with a storeJavaClass guard as defence in
depth (FIX-02; D-11, D-12).

Purpose: a USE line or qualified type naming a package (`use java.io`) reaches resolveClassByName;
the peer answers "not found", extractPackageName("java.io") gives "java", and storeJavaClass tries to
store a class `io` beside the existing package `io`, leaving the class without a container.
Output: `isKnownJavaPackage`, the caller check in `tryResolveJavaReference`, the storeJavaClass
collision handling, and `test/java-package-name-collision.test.ts`.
</objective>
