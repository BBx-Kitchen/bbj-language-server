<objective>
Give IntelliJ a plugin-owned config file type, applied to the configured file wherever it lives and
whatever it is called, carrying the bbx TextMate grammar and the config icon, and kept out of the
language server.

Purpose: CFG-02 and ROADMAP criterion 2 on the IntelliJ side, plus the `isConfigFile` seam Phase 87
consumes.
Output: `BbxConfigLanguage`, `BbjConfigFileType`, `BbxConfigSyntaxHighlighterFactory`,
`BbjConfigFileTypeOverrider`, two icons, the plugin.xml registrations, and a registration test that
proves the config Language is not mapped to the server.
</objective>

<platform_api_notes>
D-06 asked for the exact platform APIs to be verified before naming edits. Verified against the
IntelliJ Community 2024.2 platform jars and the pinned LSP4IJ 0.21.0 that this build resolves:

- Extension point `com.intellij.fileTypeOverrider` exists and is declared `dynamic="true"`; its
  interface is `com.intellij.openapi.fileTypes.impl.FileTypeOverrider` with the single method
  `FileType getOverriddenFileType(VirtualFile)`. The platform ships two implementations
  (`LightEditFileTypeOverrider`, `UserFileTypeOverrider`), so the mechanism is live, not vestigial.
- The `<fileType>` bean supports `fileNames` and `fileNamesCaseInsensitive` attributes in addition
  to `extensions`, so the default config filenames can be claimed statically.
- `TextMateSyntaxHighlighterFactory.getSyntaxHighlighter` resolves its grammar via
  `TextMateService.getLanguageDescriptorByFileName(file.getName())` — by the OPENED FILE'S NAME.
  A custom-named config file therefore gets no grammar from the stock factory; this is the gap the
  plugin-owned factory in Task 2 closes.
- `TextMateHighlighter(Lexer)` and `TextMateHighlightingLexer(TextMateLanguageDescriptor, int)` are
  both public, and `TextMateService.getLanguageDescriptorByFileName(CharSequence)` is public.
- `FileContentUtilCore.reparseFiles(Collection)` and
  `FileTypeManagerEx.getInstanceEx().makeFileTypesChange(String, Runnable)` both exist for forcing
  re-detection after the configured path changes.
</platform_api_notes>
