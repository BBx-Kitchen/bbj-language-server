<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| language server → LSP4IJ JSON boundary | the pushed notification and the request response are deserialized by LSP4J's Gson into a plugin DTO |
| IDE settings → plugin | `BbjSettings.State.configPath` is an arbitrary user string read in the pre-answer branch |
| cached path → indexing threads | the file-type override (plan 84-05) reads this cache off the EDT during indexing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-84-13 | Tampering | Gson deserialization of the new DTO | medium | mitigate | The DTO carries only String and boolean fields (no numeric sentinel to overflow) and is covered by a boundary test running LSP4IJ's own `MessageJsonHandler`, the same deserializer the live connection uses |
| T-84-14 | Denial of service | notification handler blocking a platform thread | medium | mitigate | The handler writes one volatile field synchronously and defers every UI call into `invokeLater` behind a project-disposed guard; it never calls back into the language server |
| T-84-15 | Tampering | stale cache mis-classifying a file during indexing | medium | mitigate | The cache field is `volatile`, so an indexing-thread read always observes the last completed write; last push wins by construction |
| T-84-16 | Information disclosure | the resolved path surfaced in a balloon and in the settings UI | low | accept | The path is the user's own configured value; no token or credential enters this payload, matching the plugin's existing rule that secrets never travel in argv or notifications |
| T-84-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no package-manager install task and no new dependency; the LSP4IJ pin is unchanged and its version-pin test still gates it |
</threat_model>
