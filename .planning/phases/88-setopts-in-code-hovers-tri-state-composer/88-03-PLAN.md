<objective>
Expose the scanner as the two document-aware requests both IDE clients drive, and add the
compose-new codegen DISC-06 requires: `bbj/composer/setopts/decodeInCode` (position → shape,
edit gate, prefill selection) and `bbj/composer/setopts/composeTriState` (tri-state selection →
canonical block text).

Purpose: every existing `bbj/composer/*/decodeCall` handler takes a single line of text. The
in-code decode needs multi-statement context, so it cannot join `composerHandlers` — that object
is registered in `main.ts` BEFORE `createBBjServices` runs and its handlers receive only plain
JSON. This plan builds the request family on the `compile-command.ts` /
`resolved-config-path-request.ts` precedent instead: a named method constant, a `Deps` interface,
a `createXHandlers(deps)` factory and a `registerXRequests(connection, deps)` wiring function.

Output: `setopts-in-code-request.ts`, the catalog's mask/block generators, the `main.ts` wiring,
and the round-trip test that proves a composed block reads back as a safe chain.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IDE client → language server (custom JSON-RPC) | `uri`, `line`, `character` and a whole tri-state selection arrive from an untrusted client payload |
| request layer → document mutation (client-side) | The `absolute` / `chain` edit payloads this layer emits are what a client will write into the user's file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-88-01 | Tampering | `decodeInCode` edit gate | high | mitigate | `editable` is assigned directly from the scanner's `safe` flag with no second opinion; an unsafe result carries no `chain` payload and no `initial`, so a client that ignores `editable` still has nothing to apply |
| T-88-02 | Tampering | generated `IOR`/`AND` masks | high | mitigate | Masks are built from an explicit `MAX_BYTES`-wide all-zero (`IOR`) or all-`0xFF` (`AND`) base; Task 1 asserts the full width for every catalog bit, so no unmodelled or reserved byte is disturbed |
| T-88-03 | Tampering | mask and hex literal parsing | medium | mitigate | ASVS V5: reuses `parseVector`'s undefined-on-unparseable contract through the scanner; the request layer adds no lenient re-parse |
| T-88-08 | Denial of Service | `decodeInCode` document resolution | medium | mitigate | Resolution is `LangiumDocuments.getDocument` only — the already-open in-memory document. No filesystem read and no `getOrCreateDocument`, so a client cannot make the server load arbitrary paths |
| T-88-09 | Tampering | out-of-range or malformed client params | medium | mitigate | A `line`/`character` outside the document resolves to a leaf the scanner declines, returning `found: false`; Task 2 pins the missing-document and no-shape cases as non-throwing |
| T-88-SC | Tampering | npm/gradle installs | high | accept | This plan installs no package; 88-RESEARCH.md §"Package Legitimacy Audit" records the phase as not applicable |
</threat_model>
