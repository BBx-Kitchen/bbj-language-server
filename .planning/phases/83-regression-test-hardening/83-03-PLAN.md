## Flagged assumptions

Surfaced, not dropped. Each needs a human read at verification time.

1. **A constant-pool reference is a coarser claim than a class-level annotation.** The descriptor can
   appear because the class itself is marked, or because one of its members is. The canary therefore
   asserts exactly what it checks — "the class file references the experimental descriptor" — and
   says so in its assertion message. That is enough for the purpose: when the vendor graduates the
   API and removes the marker from the class and its members, the descriptor disappears and the
   canary goes red, which is the re-audit trigger the requirement asks for.
2. **The icon behavioural test may not be writable at all.** The platform's icon fields resolve
   through an icon manager that falls back to a dummy implementation when no application is running,
   so the mapping may well work headless — but this is a probe, not a fact. If the probe throws, D-08
   says the test is dropped and the reason recorded, never stubbed.
3. **The default branch of the icon mapping cannot be covered headless in any case.** It delegates to
   the vendor superclass, which needs a running application. The behavioural test therefore covers
   only the kinds mapped to a concrete icon field, and the SUMMARY records the excluded branches.
4. **The version-pin test asserts the build classpath, not the runtime.** A plugin descriptor cannot
   pin the version of a dependency plugin the IDE resolves at run time; that is the known limit
   81-07 already hit. The SUMMARY records it and names the reflective diagnostic-message read as the
   standing runtime defence.

    **(a) The class-file helper.** Create `Lsp4ijClassFileMarkers` in the test package

    `static byte[] classBytes(Class<?> type)` resolves `"/" + type.getName().replace('.', '/') + ".class"`
    through `type.getResourceAsStream(...)`, reads it fully, and fails the test with a message naming
    the class when the stream is null — never returns an empty array.

    `static java.util.Set<String> constantPoolStrings(byte[] classFile)` parses the class file header
    (four magic bytes, two minor, two major, two constant-pool count) and then walks the constant
    pool by tag, collecting the text of every UTF8 entry. The per-tag sizes it must handle: UTF8 is
    two length bytes followed by that many bytes; integer and float are four bytes; long and double
    are eight bytes and consume an extra pool slot; class, string, method-type, module and package
    are two bytes; field-ref, method-ref, interface-method-ref, name-and-type, dynamic and
    invoke-dynamic are four bytes; method-handle is three bytes. An unknown tag fails the test with
    the tag value and the entry index, rather than guessing a size and desynchronising the walk.

    `static boolean referencesAnnotation(Class<?> type, String descriptor)` returns whether
    `constantPoolStrings(classBytes(type))` contains the descriptor. Its javadoc states the exact
    scope of the claim: the descriptor is referenced somewhere in this class file — by the class
    itself or by one of its members — which is the coarser but stable form of "the marker is still
    there", and is precisely what makes a graduation detectable.
