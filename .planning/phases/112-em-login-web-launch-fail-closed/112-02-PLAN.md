## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-112-07 | Spoofing | fail-open expiry classification (#553) | high | mitigate | classifyEmToken reports malformed for every shape it cannot positively decode, and getEMCredentials deletes such a token and forces a new login (Tasks 1-2). |
| T-112-08 | Tampering | lenient base64 decoding of the payload | medium | mitigate | Strict base64url alphabet and length check before decoding, mirroring Java's URL decoder (Task 1). |
| T-112-09 | Spoofing | unsigned token (empty third segment) | medium | mitigate | Explicit empty-third-segment check, which JavaScript's split otherwise hides (Task 1). |
| T-112-10 | Spoofing | forged token with a future exp and an invalid signature | medium | transfer | By design there is no key on the client; validateTokenServerSide (em-validate-token.bbj against EM) stays the authority and is unchanged. |
| T-112-11 | Denial of service | very long token string | low | accept | The exp regex has no nested quantifiers (linear time) and the token comes from the user's own SecretStorage. |
| T-112-12 | Information disclosure | token text in logs or messages | low | mitigate | The module never logs and no message interpolates the token (Task 2 acceptance). |
| T-112-SC | Tampering | package installs | low | accept | No package is installed. |
