## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension host → spawned `java` formatter process | the formatter shells out to an external binary and reads its stdout |
| filesystem `<input>.lst` artefacts → decompile-io | polled files may be stale artefacts of an earlier, possibly crashed, run |
| unsaved editor buffer → formatter input | `unsavedContentMap` holds document text that has not been written to disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-67-08-01 | Denial of Service | never-settling format promise (P62-D2-010) | high | mitigate | Add the `else { reject(err) }` branch so any spawn error settles the promise; the regression test drives a non-ENOENT error and asserts rejection under an explicit vitest timeout. |
| T-67-08-02 | Denial of Service | unbounded concurrent formatter spawns (P62-D3-001) | medium | mitigate | Share one in-flight promise per document URI, and delete the map entry on both settle paths so the map cannot grow without bound. |
| T-67-08-03 | Tampering | stale `.lst` accepted as fresh decompile output (P62-D2-011) | high | mitigate | Gate resolution on `mtimeMs` at or after a call-start timestamp — a size match alone can no longer satisfy the poll. The regression test constructs exactly the matching-size stale-file case. |
| T-67-08-04 | Information Disclosure | a stale `.lst` from an unrelated earlier file surfaced to the user | medium | mitigate | Same mitigation as T-67-08-03: the mtime gate means content written before this call can never be returned by it. |
| T-67-08-05 | Elevation of Privilege | the formatter spawns whatever `java` resolves to on PATH | high | transfer | Pre-existing and out of scope: no `easy-fix` record covers validating the formatter binary path. Any such finding is D1 and therefore `major-refactor` per INVENTORY §3c test 6, routed to Phase 68 / Phase 69. This plan must not widen what is spawned — the tests mock `spawn` and never invoke a real binary. |
| T-67-08-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install and no dependency change; INVENTORY §3c test 3 guarantees it for every easy-fix record. |
</threat_model>
