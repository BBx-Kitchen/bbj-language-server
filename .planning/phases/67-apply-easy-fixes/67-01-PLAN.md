<phase_conventions>
These conventions bind every plan in Phase 67 (67-01 … 67-12). This plan establishes them; later
plans cite this block.

**Never `cat` a COVERAGE file.** They are 140–480 KB each. Extract exactly one finding record with:

    awk -v ID=<FINDING-ID> '$0 ~ "^id: +"ID"$"{f=1} f{print} f&&/^```$/{exit}' .planning/reviews/<NN>-COVERAGE.md

A record is ~30–60 lines. Its `classification:` field, test (5), states **the exact edit a reviewer
can name** — that clause is the authoritative instruction for the fix. Its `evidence:` field often
carries a runnable reproduction recipe — start the red test from that, do not reinvent one.

**Commit subject shape:** `<type>(<FINDING-ID>): <what changed>`. Every commit in this phase names
at least one finding ID. Types: `test(` for a red or D5 test commit, `fix(` for a code fix,
`docs(` for a comment/doc-only fix, `chore(` for a lockfile/CI-config fix.

**Commit unit per D-11/D-12/D-13:**
| Primary dimension | Commits | Notes |
|---|---|---|
| D2, D3, D7 | 2 — red `test(...)` then green `fix(...)` | the pair is the atomic FIX-01 unit |
| D5 | 1 — `test(...)` | test-is-the-fix; `fail_before: inapplicable` (D-13) |
| D4, D8 | 1 — `fix(...)` / `docs(...)` | no behaviour change, no test |
| D6 | 1 — `chore(...)` | tool-native check (D-16) |
A record whose own text contradicts its dimension default overrides it, and the override is argued
in that ledger row.

**Per-commit verification (D-09):** from `bbj-vscode/`, `npm run build` then
`npx vitest run <only the test files this fix touches>`. Never a full-suite run per commit.

**Per-plan verification (D-09):** one full baseline-delta run at the end of each plan — see the
final task of every plan.

**Do not edit** `.planning/reviews/INVENTORY.md` or any `6N-COVERAGE.md`. They are closed.
</phase_conventions>
