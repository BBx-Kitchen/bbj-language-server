<objective>
Make concurrent completion requests on different documents each honor their own cancellation token (RESP-04, #498).

Purpose:
- Today `getCompletion` writes the request's token into a field on the singleton provider, so a second request overwrites the first's token.
- The per-prefix memo also creates its shared in-flight lookup with the first caller's token, so cancelling that caller can reject every other waiter.

Output:
- `AsyncLocalStorage` token propagation.
- A token-free shared lookup.
- Two regression tests.
</objective>

| T-91-04 | Tampering | request-scoped token on the singleton provider | medium | mitigate | `AsyncLocalStorage` per request, the removed field, and the two-document token test |

| T-91-06 | Denial of Service | a token-free shared lookup keeps running after every waiter cancelled | low | accept | the lookup is a one-time, latched class-index build or an in-memory scan shared by all requests; each waiter returns at its own token check |
