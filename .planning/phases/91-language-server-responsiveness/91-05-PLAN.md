<objective>
When the interop breaker closes after an outage, re-check open documents once, so stale "unresolved class" diagnostics clear without the user typing and without `clearCache()` (RESP-02 recovery, D-04).

Purpose: plan 91-03 makes transport failures uncached and signals recovery. Nothing yet re-links the documents that were built during the outage. A reconnected peer is a fresh backend instance with no memory of the custom classpath (RESEARCH Pitfall A), so the classpath and implicit imports must load again before the re-check.

Output:
- `java-class-reload.ts`, a helper extracted from `main.ts`'s refresh steps 2-4;
- the `main.ts` wiring;
- tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reconnected java-interop peer → cached class answers | a fresh peer instance starts from the default classpath and does not remember the custom one |
| recovery handler → document builder | a rebuild can collide with the initial workspace build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-91-16 | Tampering | recovery re-check against a peer without the custom classpath, which caches user classes as a genuine not-found | high | mitigate | the helper reloads the classpath and implicit imports before `update`; call-order test |
| T-91-17 | Denial of Service | recovery rebuild during the initial build, or repeated rebuilds | medium | mitigate | deferral until the one-shot first-Validated block; once-per-recovery test |
| T-91-18 | Repudiation | silent failure of the recovery re-check | low | mitigate | `recheckAfterInteropRecovery` logs failures with `console.error` and never shows a popup |
| T-91-SC | Tampering | npm/pip/cargo installs | low | accept | no dependency is added |
</threat_model>
