## Part B was re-scoped by measurement — read this before touching the cache step

The seed says `verifyPlugin` downloads "210.18 MB across four IDEs" and asks for the IDE directory to be cached. **The 210.18 MB is not the IDEs.** Facts established at planning time from the run log of 35064112482 and from this machine's caches:

- The line `Total amount of plugins and dependencies downloaded: 210.18 MB` is printed by the Plugin Verifier itself at the end of verification. It counts the verifier's own **plugin and dependency** downloads, which land in `~/.pluginVerifier/loaded-plugins` — locally exactly 211 MB. That directory is cacheable and is what this plan caches.
- The IDEs are resolved by **Gradle**, not by the verifier, and are read from `~/.gradle/caches/9.7.1/transforms/<hash>/transformed/ideaIC-<version>` (quoted verbatim from the run log). IPGP 2.18.1 downloads them as ordinary Gradle dependencies: `ideaIC-<version>.tar.gz` under `~/.gradle/caches/modules-2/files-2.1/idea/ideaIC/`.
- Measured sizes on this machine for the exact builds CI verified (IC-242.26775.15 = 2024.2.6, IC-243.28141.41 = 2024.3.7.1, IC-251.29188.72 = 2025.1.7.2, IC-252.28539.97 = 2025.2.6.3, plus the 2024.2 compile platform): **tarballs 841 MB – 1.2 GB each, 4.9 GB total; extracted 2.6 – 3.4 GB each, ~14.6 GB total.**
- A GitHub Actions cache is limited to **10 GB per repository** (LRU plus 7-day eviction). This repository currently uses 62.8 MB across one entry.

Caching the IDEs is therefore rejected on measurement, not on difficulty: 4.9 GB of tarballs would consume half the repository's entire cache budget and evict everything else, ~14.6 GB extracted exceeds the budget outright, and restoring several GB from the cache service would not beat JetBrains' CDN. `intellijPlatformIdesCacheEnabled=true` (default `false` in 2.18.1, confirmed in the pinned jar) would relocate the **extracted** IDEs to `bbj-intellij/.intellijPlatform/ides` — the ~14.6 GB variant, i.e. worse.

**Do not** cache `~/.gradle/caches`, do not set `intellijPlatformIdesCacheEnabled`, and do not shrink the IDE set or soften `failureLevel` (explicitly rejected by the seed — one gate, same settings everywhere). Record the measurements in a comment above the cache step so the next reader does not retry the rejected idea.

- **No GitHub issue is to be filed.** Tracked in the seed by decision.
- `bbj-intellij/build.gradle.kts` is not modified. `build.yml`, `pr-vsix.yml`, `deploy-docs.yml` and `workflow-hygiene.yml` are not modified.
