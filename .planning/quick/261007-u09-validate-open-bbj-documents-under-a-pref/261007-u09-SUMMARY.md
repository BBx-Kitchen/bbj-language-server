# Phase 261007-u09 Plan 01: Validate open BBj documents under a PREFIX Summary

**Every BBj document open in an editor now gets Langium validation, the live parser, BBjCPL and full linking even when it lives under a PREFIX directory; closing it publishes empty diagnostics and rebuilds it from disk as a library file.**

## Commits

- ca65231b: `fix(ls): validate and fully link BBj documents open in the editor even under a PREFIX directory` (predicate, builder sites, linker, scope-local, first tests)
- 200a8e2a: `fix(ls): clear diagnostics and rebuild a PREFIX document as a library file when its editor closes` (close release, publish guard, `didCloseDocument`, close tests, one adjusted existing test)

Task 3 needed no code change, so it has no commit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Close listener passed a string where a URI was needed**
- **Found during:** Task 2 (close tests failed with no empty publish)
- **Issue:** I reused `UriUtils.normalize(URI.parse(...))`, which returns a string, as the `URI` argument of `releaseClosedLibraryDocument`; `isExternalDocument` threw and the existing try/catch logged it.
- **Fix:** parse once into a `URI`, normalize only for the `lastSavedVersion` key.
- **Files modified:** bbj-vscode/src/language/bbj-document-builder.ts
- **Commit:** 200a8e2a

**2. [Rule 1 - Test contradicting new behavior] live-parse-scheduling expected an open PREFIX document to arm nothing**
- **Found during:** Task 2 verification run
- **Issue:** `a change event for a non-file: uri, and for a document under a configured PREFIX directory, arms nothing` asserted exactly the behavior this task removes.
- **Fix:** split into a non-file uri test (unchanged assertion) and `a document under a configured PREFIX directory is live-parsed once it is open`.
- **Files modified:** bbj-vscode/test/live-parse-scheduling.test.ts
- **Commit:** 200a8e2a

**3. Test detail: body-resolution case does not assert `instanceAccess`**
In this grammar `#` on an assignment target sets `instanceAccess` on the `Assignment`, not on the `SymbolRef`, so the case asserts that the `secret` reference resolves to the `FieldDecl` instead.

Otherwise, the plan was executed as written. `shared.lsp.DocumentUpdateHandler` is constructible in the hermetic harness, so no direct construction was needed.
