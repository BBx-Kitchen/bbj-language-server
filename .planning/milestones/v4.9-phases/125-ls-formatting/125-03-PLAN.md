<objective>
Build the language server's format path behind the scenes: a bounded handler that reads only the
open buffer, a format service that turns `formatProgram` outcomes into minimal edits with stale,
cancel and document-kind guards, and the Langium `Formatter` adapter (FMT-01, FMT-02, FMT-03,
FMT-04, FMT-05, FMT-12; D-12, D-14, D-15). The service is registered in DI, but neither the
`lsp.Formatter` slot nor the handler registration in `main.ts` is added here: the server starts
advertising formatting only in plan 125-06, together with VS Code's provider removal.

Purpose: SC1 and SC2 of the phase (bbj-ls output as minimal line edits; on-save never waits for the
workspace, cancellation is silent, stale edits are never applied) and the FMT-12 part of SC4.
Output: `bbj-format-service.ts`, `bbj-formatting-handler.ts`, `bbj-formatter.ts`, the DI slot, the
extended test double and three test files.
</objective>

request for an open BBj document into minimal line edits through bbj-ls's `formatProgram`, owns the

`this.javaInterop.formatProgram(params, token)`. Then, in this order: a cancelled caller token gives
`[]` with a debug line (per D-14); `request.current()` missing or at another version gives `[]`

message, no document text); plan 125-04 turns it into the user messages.
