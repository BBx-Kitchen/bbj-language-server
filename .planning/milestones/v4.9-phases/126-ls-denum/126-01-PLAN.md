<objective>
Serve `bbj/denum` from the shared language server (DEN-01): one orchestration core,
`BBjDenumService.run`, reads the open buffer, sends it to bbj-ls `denumProgram`, re-checks the
version, builds one minimal line edit and applies it itself through a versioned
`workspace/applyEdit` (D-14, D-15), then shows one message (D-10). The result returns status,
reason, edit, version and diagnostics for the caller. Guards: tokenized input never sent, non-BBj or
closed documents refused, stale and refused edits never applied (D-07), one run per document at a
time, cancellation silent.

Purpose: SC2's "Denumber replaces the open buffer ... as one edit served by bbj/denum, and the result
carries DENUM's diagnostics". The VS Code command still uses its old path until Phase 127; in this
phase `bbj/denum` is reached through tests and, from plan 126-04, through the format offer.
Output: `denum-command.ts`, `denum-notifications.ts`, `bbj-denum-service.ts`, two senders, the DI
slot, the `main.ts` registration and three test files plus two shared test helpers.
</objective>

its open document (it checks `documentChanges` only); LSP4IJ 0.21.0 never reads the version and
always answers `applied: true`, so the server's own re-check right before sending is the primary
guard.

Live facts (RESEARCH "Live Probe"): `0010 print 1\n0020 goto 0010\n` answers
`{"text":"L10: print 1\ngoto L10\n","diagnostics":[],"denumbered":true}`; unnumbered and empty text
answer `denumbered: false` with the text unchanged; CRLF is preserved; an absent `canonicalName`
is never superseded, the same one is (`-32800`, which the lane reports as `cancelled`); the
tokenized prefix is exact, lowercase, at offset 0.
