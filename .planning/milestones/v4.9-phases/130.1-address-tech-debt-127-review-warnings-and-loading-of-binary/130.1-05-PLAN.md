<objective>
Close 126 WR-02 per D-16: `bbj/denumDiagnostics` carries the document version the list was computed
for, and the VS Code client drops the placement (log copy only) on a mismatch. The notification is
sent by this repo's language server (`bbj-notifications.ts` via `BBjDenumService`), so bbj-ls is not
changed.

User resolution 1 (2026-10-05): mirror-based post-edit stamping as researched. After an applied
edit the server waits, bounded, until its own `TextDocuments` mirror holds the denumbered text, and
stamps that mirror version (each client sends its own version numbers in didChange); if the mirror
never catches up, it sends the list without a version so clients log it only. With no edit needed it
stamps the live version. Never `V + 1` (research Answer 6, Pitfall 6).

IntelliJ places nothing today (it only logs the list); its model field and contract update are plan
08, which depends on this plan because its contract test reads `denum-notifications.ts`.

Purpose: a keystroke typed right after Denumber can never get stale problems placed on the wrong lines.
Output: the optional `version` field, the server stamping, the client check, tests.
</objective>
