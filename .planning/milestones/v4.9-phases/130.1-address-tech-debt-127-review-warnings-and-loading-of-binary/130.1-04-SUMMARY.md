# Phase 130.1 Plan 04: Numbered and Tokenized Documents Out of Diagnostics Summary

**One pure `classifyDocumentText` classifier gates the validator, the compiler-check arm gate and the debounce timer re-check, so tokenized text reports nothing and line-numbered text reports a single Denumber hint.**

## Performance

- **Duration:** 4 min
- **Started:** 2026-10-05T06:51:20Z
- **Completed:** 2026-10-05T06:55:44Z
- **Tasks:** 2
- **Files modified:** 7

## Accomplishments
- `validateDocument` classifies the live text first. Tokenized returns `[]`; line-numbered returns one Information diagnostic (code `bbj-line-numbered`, line 0) naming "Denumber BBj Program"; both clear the stored verdict and kept check. Normal text takes the existing path unchanged.
- `shouldCompileWithBbjcpl` refuses non-normal text, covering `runBbjcplForDocuments` and every `armLiveParseForDocument` path. The `debouncedCompile` timer callback re-classifies the text it is about to check and returns before any request, so a cycle armed before the text turned numbered or tokenized publishes nothing.
- The magic exists once as text (`TOKENIZED_BBJ_MAGIC_TEXT`), used by the classifier, the builder's PREFIX `USE` skip and the format service alias.
