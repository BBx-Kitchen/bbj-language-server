<objective>
Keep tokenized and line-numbered documents out of diagnostics in the shared language server
(D-07 server side, D-08, D-09; folded todo "Skip syntax checking for line-numbered programs").
One pure classifier decides per text; the document validator returns no diagnostics for a tokenized
document and one Information diagnostic pointing to Denumber for a line-numbered one; the
live-parse/BBjCPL check never arms for either, and a cycle armed earlier re-checks the live text
before it publishes (research Answer 5: gating `validateDocument` alone leaks compiler diagnostics).

Research correction applied: `bbj-document-builder.ts:1142` skips tokenized files only when loading
PREFIX `USE` targets, not in the workspace scan; scanned documents are built without validation and
publish nothing, so no workspace-scan change is needed.

Purpose: an IntelliJ or VS Code user who opens a numbered program sees one clear hint instead of a
wall of syntax errors, and a tokenized program that reaches the server shows nothing.
Output: `bbj-document-kind.ts`, the shared magic text constant, gates in the validator and builder,
tests.
</objective>
