<objective>
Give IntelliJ the same open-time offer for tokenized (binary) BBj programs that VS Code has, per D-06:
an editor banner with "Decompile & Replace" and "Open Read-only". The plugin runs bbjlst itself from
the configured BBj Home and mirrors the VS Code behaviour fixed in plan 01 and plan 02: resolve the
real path (D-02 behaviour), run `bbjlst -l [-xlst] -d<private temp dir> <file>`, judge success by the
listing (exit code is 0 even on failure), replace atomically in the same directory, remove the
private directory. Decompile stays client-side (moving it into bbj-ls is deferred).

User resolution 2 (2026-10-05): the banner covers BBj-typed files only (it extends
`BbjNotificationProviderBase` and keeps its file-type guard); what IntelliJ does with `.pub` or
extensionless tokenized files is recorded in the final hand check only.

Purpose: an IntelliJ user who opens a tokenized program can turn it into editable source or look at
it read-only without leaving the IDE.
Output: a new `tokenized` package (plain-Java detection and bbjlst core plus the platform task), the
banner provider and its registration, JUnit tests, a real-bbjlst JUnit test, source guards and a
contract test that pins the magic bytes against `bbj-vscode/src/tokenized-bbj.ts`.
The LSP4IJ `isEnabled` gate (D-07 client side) is plan 08.
</objective>
