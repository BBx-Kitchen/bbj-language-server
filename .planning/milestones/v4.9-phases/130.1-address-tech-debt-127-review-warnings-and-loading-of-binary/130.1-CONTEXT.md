<decisions>
## Implementation Decisions

### Binary scope: in-place decompile (backlog 999.1)
- **D-01:** This phase absorbs backlog 999.1. Diagnose why "Decompile & Replace" from the open
  prompt does not rewrite the tokenized file as source in place (127-06 hand check step 15, BBj
  26.03), and fix it in the existing VS Code client path (`Commands.cjs`, `decompile-io.ts`,
  `process-args.ts` `buildDecompileArgv`). Decompile is NOT moved into bbj-ls in this phase.
- **D-02:** WR-01: the open prompt and the decompile guard use one shared detection rule. A
  symlinked tokenized file is resolved with `realpath` and the target is checked and decompiled
  (behaviour before phase 127). The #585 hardening (no FIFO/device open, lstat/O_NOFOLLOW/fstat on
  the resolved path) must still hold for the resolved target.
- **D-03:** WR-01: an I/O error (EACCES, EBUSY, read race) is not reported as "not a tokenized BBj
  program"; the user gets a message that names the real cause.
- **D-04:** WR-02: Denumber invoked on a tokenized (binary) file detects that up front and shows a
  warning that names the "Decompile Tokenized BBj Program" command, instead of the raw VS Code
  "file seems to be binary" error. No chaining, no action button.
- **D-05:** Backlog 999.1 is removed from ROADMAP.md once in-place decompile passes the phase's
  hand check.

### IntelliJ binary behaviour
- **D-06:** Opening a tokenized program in IntelliJ shows an editor banner (same style as the
  phase 128 line-numbered banner) with "Decompile & Replace" and "Open Read-only". The plugin runs
  bbjlst itself from the configured BBj home, mirroring the VS Code argv (`-l`, plus `-xlst` for
  `.lst`) and the D-01/D-02 behaviour.
- **D-07:** Tokenized documents are kept out of diagnostics on both sides: the shared language
  server sends no parse/validation diagnostics for an opened tokenized document (it already skips
  them in the workspace scan, `bbj-document-builder.ts:1139`), and each IDE client also avoids
  handing a tokenized file to the LS where it can.

### Line-numbered programs (folded todo)
- **D-08:** When the LS detects that a document is line-numbered, it suppresses parser and
  validation diagnostics and sends one informational diagnostic that points to Denumber. After
  denumbering, the document is validated normally again.
- **D-09:** This applies in both IDEs (one LS rule, no client gating).

### splitSingleLineIF migration (127 WR-03, also 125 WR-01)
- **D-10:** Re-run the idempotent `migrateSplitSingleLineIf` from an `onDidChangeConfiguration`
  listener filtered with `affectsConfiguration('bbj.formatter.splitSingleLineIF')`, so a late
  old value (Settings Sync pull, hand edit, workspace settings change) is migrated without reload.
- **D-11:** Half-done migration: when the new key already holds the same boolean as the old key,
  the migration removes the old key.
- **D-12:** Keep the LS legacy fallback (`usesLegacySplitKey`, `userKeyFor`, the undefined check in
  `bbj-format-settings.ts`) for IntelliJ or other clients that may still send the old spelling;
  the researcher confirms what IntelliJ sends.

### Ride-along debt
- **D-13:** 127 WR-04: Denumber `when` clauses drop the dead `resourceLangId == bbx` branch (or
  `createDenumberCommand` checks the language for an argument path).
- **D-14:** 127 IN-01: `canRewriteInPlace: true`, drop the redundant second `isTokenizedFile`, drop
  the `fileName` alias. IN-02: remove the `bbj-decompiled-*` temp dir on failure.
  IN-04: replace the free-text `/denumber/i` and `tools/formatter` source greps with
  behavioural or narrowly targeted checks.
- **D-15:** 127 IN-03 (`indentWidth` is now integer 0-16): release note / docs mention only, no
  clamp.
- **D-16:** 126 WR-02: `bbj/denumDiagnostics` carries the document version the list was computed
  for. The notification is sent by this repo's LS (`bbj-notifications.ts`), so no bbj-ls change.
  Both clients (VS Code `placeProblems` in `extension.ts`, IntelliJ `BbjLanguageClient`/
  `DenumDiagnosticsPresenter`) drop the placement (log copy only) on a version mismatch.
- **D-17:** 130 WR-02/WR-03: docs message tables say repeats are silent; QA rows name their files
  and mention the open prompt (VS Code rows 31/36, IntelliJ row 40).
- **D-18:** ROADMAP.md staleness from the audit: milestone heading, progress table rows and the
  milestone row's plan count are brought up to date.

### Claude's Discretion
