<objective>
Collapse the two status-bar widgets and their two factories onto one base each, so a change to the
widget shape is written once (D-13), end the tooltip asymmetry (D-14), unify the Open Settings call
on the exact-class form (D-15), and re-point the guards that pinned the old per-file shape (D-16).

Purpose: ROADMAP criterion 5. This plan is **last in the phase by design** — the ROADMAP's ordering
note requires the base to be extracted after IOP-02 and IOP-03 have changed what the widgets poll
and report, so the base is taken from the final widget shape rather than refactored twice. The Java
widget's status switch gained a wrong-peer branch in plan 95-01 and the service's polling changed in
plan 95-02; both are settled before the extraction begins.

The consolidation ships as an abstract generic base plus two thin subclasses, following the Phase 93
D-05/D-06 precedent. #620's literal wording asks for one concrete class parameterised at
construction; that shape is rejected for the third time in this milestone because it turns a wiring
mistake into a runtime no-op instead of a compile error — and here the two status enums are
unrelated types, so a generic base keeps every difference compile-time checked.

Output: two new base classes, four thinned classes, one re-pointed guard, and an installable plugin
build for UAT.
</objective>
