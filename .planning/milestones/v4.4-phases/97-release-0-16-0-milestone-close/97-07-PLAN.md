gate: the Preview run triggered by the landing merge must finish green and the maintainer must
install that preview build in both IDEs.

**Facts verified at research time that the runbook must encode, not re-derive.**
- `manual-release.yml`'s graph: `verify` -> (`publish-vscode` ∥ `publish-intellij`) -> `tag-release`
  -> `create-release`. `verify` uploads `language-server`, `vscode-extension` and `intellij-plugin`,
  all with `retention-days: 1`. The version input must match `x.y.0` and be strictly greater than
  `package.json`'s current value. `tag-release` commits the version bump, tags and pushes, and only
  runs after **both** publishes.
- `publish-intellij` does **not** download the `intellij-plugin` artifact. It downloads only
  `language-server` and runs the Gradle publish task, which publishes a freshly rebuilt zip — not
  the bytes `verifyPlugin` checked. A by-hand reconciliation must therefore upload the downloaded
  artifact directly rather than re-running that job.
- The JetBrains Marketplace exposes a documented direct-upload endpoint taking a multipart
  `pluginId` / `file` / `channel` and a bearer token; the plugin id is 30033. Whether the existing
  publishing token works as that bearer token is **UNVERIFIED** — the runbook must say so and give
  the web-UI upload as the fallback.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator shell -> marketplace publishing APIs | A publishing token crosses into a hand-run command; a leak publishes under the maintainer's identity. |
| CI artifact store -> hand-run recovery | Verified bytes exist for 24 hours only; after that, any "recovery" publishes different bytes. |
| Preview publish -> real users | The preview channel is public; a red preview must never be waved through to a release dispatch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-97-21 | Information Disclosure | Publishing tokens in hand-run commands | high | mitigate | The runbook mandates environment-variable tokens placed last, never inlined or written to a file; a token-shape grep over the runbook is a task gate. |
| T-97-22 | Tampering | Published artifact identity | high | mitigate | Recovery paths publish the failed run's own downloaded artifact and compare sha256 with the recorded hash; the runbook states plainly that the Gradle publish task rebuilds instead of re-uploading. |
| T-97-23 | Repudiation | Half-released state | high | mitigate | The tiered failure rule and the never-bump-to-paper-over rule are written into the runbook, so a half-release is reconciled rather than hidden behind a new version. |
| T-97-24 | Denial of Service | Recovery window | medium | accept | Artifact retention stays at one day — raising it is a workflow change and out of scope; the runbook mitigates by making the download the first action on any failure. |

No package-manager install occurs in this plan, so the package-legitimacy gate does not apply.
</threat_model>
