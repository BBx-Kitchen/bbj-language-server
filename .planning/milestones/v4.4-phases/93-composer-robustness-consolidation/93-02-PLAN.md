<objective>
Move the SETOPTS raw-tail validity rule to the language server, where every other composer's rule
already lives, and put the resulting verdict on the wire for both IDEs.

Purpose: COMP-04 (#607), server half. `setoptsPreview` already runs `/^[0-9A-Fa-f]*$/` against the
raw tail at `setopts-catalog.ts:357` and throws the result away — it only gates whether the tail is
applied. Meanwhile `SetoptsComposerDialog:213-218` re-implements the same rule in Java with its own
message, which is exactly the client-side duplication the standing "the server owns validation;
dialogs render its verdict" convention forbids, and the reason both SETOPTS dialogs call
`setOKActionEnabled(true)` unconditionally while the other four gate on `p.valid`.
Output: `valid` + `rawTailError` on `SetOptsPreview` and `valid` on the composeTriState result, on
both hosts, consumed by the VS Code webview. Plan 93-08 consumes it in the IntelliJ dialogs.
</objective>

| Boundary | Description |
|----------|-------------|
| language server → IDE host (JSON-RPC `bbj/composer/setopts/*`) | an untrusted-shape response crosses into both hosts |
| composer dialog/webview → developer's source file | accepted input becomes a write into live source |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-93-04 | Tampering | SETOPTS write path | high | mitigate | The validity rule has one definition, server-side, and both hosts render it — removing the second Java rule that had already silently diverged from the server's check |
| T-93-05 | Tampering | `SetoptsPreview` / composeTriState JSON boundary | high | mitigate | Java `boolean valid` defaults to `false`, so a malformed or partial response refuses the write; pinned by a no-key envelope case in `ComposerModelsJsonBoundaryTest` |
| T-93-06 | Information Disclosure | `rawTailError` message | low | accept | The message is a fixed literal describing the hex rule; it echoes no user input and no path, so there is nothing to disclose |
| T-93-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan adds zero packages to `bbj-vscode/package.json` or `bbj-intellij/build.gradle.kts`; no install task exists, so the package-legitimacy gate has nothing to clear |
