<objective>
Give the five `Configure*Intention` classes one shared base so the four members that are identical in
all five — family name, write-action policy, launch call and preview construction — are written once.

Purpose: COMP-08 (#618). Per D-05 this ships as an abstract base plus five thin no-arg subclasses,
not the "single data-driven registration" the issue proposes: IntelliJ's `<intentionAction>`
extension point accepts only `<className>`, instantiates via a no-arg constructor, and gives the
instance no way to learn which registration produced it, so one class registered five times cannot
vary its text, `Kind` or keyword. This is a deliberate, platform-forced deviation from the issue's
wording and must be recorded as such when #618 is closed.
Output: `ComposerIntentionBase`, five slimmed subclasses, one new guard, one re-pointed guard.
</objective>
