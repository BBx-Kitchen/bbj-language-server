<objective>
Give the three plugin-bundled tool scripts one path-resolution home, so `web.bbj`, `em-login.bbj`
and `em-validate-token.bbj` stop being looked up by three near-identical private methods across two
files.

Purpose: EM-05 (#614). `BbjRunActionBase.getWebBbjPath()` (:240-257),
`BbjRunActionBase.getEmValidateBbjPath()` (:259-281) and `BbjEMLoginAction.getEMLoginBbjPath()`
(:220-234) are the same nine lines three times — same plugin id, same `findEnabledPlugin`, same
resolve-under-the-tools-directory, same existence check, same return-null-on-anything. Only the
script filename varies. This also retires the duplicated plugin-bundle path resolution recorded as
advisory finding IN-02 in `79-REVIEW`.
Sequencing: this plan is deliberately the phase's first (wave 1) per D-09. EM-03's new validation
class consumes this resolver for its `em-validate-token.bbj` path, so building the resolver first
means that class is written once against its final dependency instead of being refactored.
Output: `BbjToolScriptResolver` plus its unit test, three retired methods, three converted call sites.
</objective>
