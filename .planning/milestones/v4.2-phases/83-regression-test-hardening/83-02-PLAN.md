## Flagged assumptions

Surfaced, not dropped. Each needs a human read at verification time.

1. **A third seam extraction beyond the two named in the phase boundary.** 83-CONTEXT.md's Phase
   Boundary names two agreed extractions (the pipeline seam and the Settings failure path).
   `NodeAvailability` is a third, and it exists for one reason: D-12 requires behavioural coverage of
   both notification-provider branches, and `collectNotificationData` cannot run without a live
   `Application` because it reads `BbjSettings.getInstance()` and a `VirtualFile`. The extraction is
   mechanical — the same conditions in the same order — and is the minimum that makes the decision
   executable under C-01's plain-JUnit constraint. If a reviewer prefers the branches stay covered by
   source text alone, this task is the one to revert.
2. **Adding a component to a record is source-compatible here, not in general.** `NodeLookup` and
   `HomeLookup` are constructed only inside `BbjSettingsLookups`; every other file reads them through
   accessors. Confirm with a grep before editing, and if a construction site turns up outside that
   file, add static factories instead of widening the canonical constructor.
3. **The catch is at the lookup layer, not in the debouncer.** D-13 allows either. The lookup layer
   wins because it produces a typed result that flows through the existing apply path without
   changing the debouncer's contract or its constructor arity. The consequence is that a lookup
   function which still throws — a future one, not these two — would still escape the scheduled task;
   `DebouncedLookupFailureDeliveryTest` pins that fact so the reason the lookups must not throw is
   itself executable.
4. **A configured-but-unusable Node path never consults the cached download.** That is today's
   behaviour, and this plan pins it rather than changing it. It is also a plausible mechanism for the
   80-UAT Windows observation ("automatic Node.js installation did not work; the user set the node
   home by hand"), because a stale configured path suppresses the cached-download branch entirely.
   Changing it is a product decision, so the finding goes to a todo and to the SUMMARY, not into this
   plan's diff.
