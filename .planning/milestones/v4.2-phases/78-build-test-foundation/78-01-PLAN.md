<objective>
Make `bbj-intellij` build and test on this host's default Temurin 25.0.4.1 JDK without any manual JDK switching, by steering the Gradle daemon itself onto JDK 17 through committed Daemon JVM criteria and pinning the compile/test JVM through the Gradle toolchain.

Purpose: BUILD-01 / issue #570. Gradle 8.x cannot run its daemon on Java 25 (the compatibility matrix tops out at Java 24), and the failure happens inside the embedded Kotlin DSL compiler in the daemon JVM before `build.gradle.kts` is even evaluated — so a `java { toolchain {} }` block alone cannot fix it. This plan is the gate for every other `./gradlew` invocation in v4.2 (STATE.md v4.2 sequencing note).

Output: a committed `bbj-intellij/gradle/gradle-daemon-jvm.properties`, a toolchain block in `bbj-intellij/build.gradle.kts`, the foojay resolver in `bbj-intellij/settings.gradle.kts`, and a recorded self-heal provisioning outcome.
</objective>

| Boundary | Description |
|----------|-------------|
| Gradle Plugin Portal → the build | The foojay resolver plugin is fetched over the network and executes inside the Gradle settings evaluation |
