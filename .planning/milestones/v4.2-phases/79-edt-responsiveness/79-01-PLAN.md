<objective>
Funnel every BBj language-server restart trigger through one guarded, coalescing entry point on
`BbjServerService`, and replace the first-crash EDT sleep with a delay scheduled on that same gate.

Purpose: today six external call sites plus two in-file sites call a public no-arg restart method
directly, so two overlapping triggers race each other into two `stop`+`start` pairs (#539), and the
first-crash recovery blocks the EDT for a full second inside `invokeLater` (#513). D-16 makes this
plan 1 of 3 and the owner of the shared `Scheduler` seam that plan 79-02 also consumes.

Output: a plain-Java `Scheduler`/`RestartGate` pair under `com.basis.bbj.intellij.concurrency`, a
production `AlarmScheduler` adapter, `BbjServerService.requestRestart(long)`, all eight call sites
redirected, and red-then-green JUnit 5 coverage (behavioural + source-guard) under `./gradlew test`.
</objective>

## Flagged assumptions

Surfaced, not dropped. Each needs a human read at verification time.

1. **EDT-04 edge-probe row is `unclassified` / `unresolved`.** The deterministic edge probe could not
   classify EDT-04 ("first-crash restart delay scheduled, never an EDT sleep") into a shape category,
   so no edge criterion was auto-derived for it. The behavioural and source-guard criteria in Task 3
   cover the requirement text itself; whether an unwritten edge remains (for example: what happens if
   the project is disposed between the crash and the scheduled restart) is not settled by this plan.
   Current handling: `doRestart()` is only reached through the Alarm, which IntelliJ disposes with the
   service, and `updateStatus()` already returns early on `project.isDisposed()`.
2. **An eighth restart site exists that CONTEXT.md's "seven callers" list does not name.** The
   crash-balloon `NotificationAction("Restart")` inside `BbjServerService.notifyCrash()` (line 194-201)
   calls the public no-arg restart method in-file. It is redirected here too — leaving it would keep a
   raw, un-coalesced `stop`+`start` path alive and contradict #539's "all triggers". This is a superset
   of D-06, not a deviation from it.
3. **Cross-window restart races are out of this plan's reach.** The gate is per-project-service scoped,
   matching the resource (one language server per project). Two projects restarting their own servers
   concurrently is correct behaviour, not a race.
