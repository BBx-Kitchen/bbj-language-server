<objective>
Put a stat-keyed memo in front of `node --version` and move every filesystem and subprocess call out
of the Settings dialog's keystroke path into a debounced background task.

Purpose: `BbjMissingNodeNotificationProvider` re-spawns `node --version` on every editor-notification
refresh pass (#543), and `BbjSettingsComponent` spawns that same subprocess plus reads directories
inside `DocumentAdapter.textChanged` and inside two `ComponentValidator` validators on every keystroke
(#541) — all of it on the EDT. D-16 makes this plan 2 of 3; it consumes the `Scheduler` seam that plan
79-01 created and touches no file that plan 79-03 touches.

Output: `BbjNodeVersionCache`, a `ThreadProbe` seam, a `KeystrokeDebouncer`, a `BbjSettingsLookups`
holder for all settings-dialog I/O, both consumers rewired, and red-then-green JUnit 5 coverage
(behavioural + source-guard) under `./gradlew test`.
</objective>

## Flagged assumptions

Surfaced, not dropped. Each needs a human read at verification time.

1. **EDT-03's edge-probe row is `unclassified` / `unresolved`.** The deterministic probe could not
   classify "the notification caches the last known version per configured path" into a shape category,
   so no edge criterion was auto-derived. The criteria in Task 1 cover the requirement text and the
   stat-invalidation decision (D-10); an unwritten edge may remain around clock skew — a binary replaced
   within the same millisecond and at the identical byte length would reuse the cached version. The
   `size` half of the key makes that vanishingly unlikely but not impossible, and no file-hash is taken
   because that would reintroduce per-refresh I/O.
2. **CONTEXT.md's verified state lists only the two `DocumentAdapter`s as the EDT-02 sites; there are
   four.** The two `ComponentValidator` validators installed on the same fields
   (`BbjSettingsComponent.java` lines 51-65 and 76-95) also run on the EDT on every keystroke — the node
   validator spawns `node --version` and stats a file, the home validator reads the BBj home directory.
   EDT-02's requirement text ("never spawns a subprocess or reads a file on the EDT") covers them, so
   Task 3 converts both validators into pure readers of the last published background result. This is a
   superset of D-12, not a deviation from it.
3. **`BbjSettingsConfigurable.reset()` still calls `BbjHomeDetector.detectBbjHome()` and
   `BbjNodeDetector.detectNodePath()` on the EDT** when the persisted fields are empty. That is the
   dialog-open path, not the typing path, so EDT-02's wording does not reach it, and D-11 explicitly
   blesses `detectNodePath()` as a PATH scan with no subprocess. Left as is; recorded here rather than
   silently ignored.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings field text (user-controlled) → subprocess spawn | The configured Node.js path is arbitrary user input that reaches `GeneralCommandLine(nodePath, "--version")` |
| Settings field text → cache key | The same user-controlled string, plus a stat of the file it names, becomes the memo key |
| Background lookup thread → EDT | Results computed off the EDT are applied to Swing components through `invokeLater` |
