<objective>
Fix GitHub issue #663 for both IDEs. RUN and CALL take a file name that is absolute, resolves through PREFIX, or sits relative to the program. Hovering the literal must show the fully resolved file name. Ctrl/Cmd-Click must open the program, or switch to its tab if it is already open. The "unresolved means warning" half already exists from #173 (`checkRunCallFileResolves`), and this plan leaves its behaviour unchanged.

Purpose: VS Code and IntelliJ (through LSP4IJ) share this language server. Today a RUN/CALL file literal resolves to no declaration, so the user gets neither hover nor go-to-definition on it.

Output:
- a new shared resolver module, `run-call-target.ts`, used by the validator, the hover provider and the definition provider, so the candidate logic is not copied three times

- one-bullet docs mentions in both IDE feature pages

Facts confirmed live at planning time (branch fix/663-run-call-navigation):
- Grammar: `CallStatement: 'CALL' fileid=Expression Err? (',' expressions+=Expression)*`, `RunStatement: 'RUN' fileid=Expression Err?`. `StringLiteral: value=(STRING_LITERAL | HEX_STRING)`. `STRING_LITERAL` is `/"([^"]|"{2})*"/`, and bbj-value-converter.ts only unescapes doubled quotes, so backslashes in a BBj string are literal.
- Langium 4.3.1: `DefaultDefinitionProvider.getDefinition` reaches `collectLocationLinks` only via `findDeclarationNodeAtOffset` and `References.findDeclarationNodes`. A string literal has no declaration, so `getDefinition` itself has to be overridden.
- `UriUtils.resolvePath(URI.file('/root/app'), '/opt/progs/x.bbj')` gives `file:///opt/progs/x.bbj`, and `path.resolve('/prefix', '/opt/progs/x.bbj')` gives `/opt/progs/x.bbj`. POSIX absolute targets already resolve as themselves.
- The same `UriUtils.resolvePath` call on `C:\progs\x.bbj` gives `file:///root/app/C%3A%5Cprogs%5Cx.bbj`, which is wrong. `URI.file('C:/progs/x.bbj')` gives `file:///c%3A/progs/x.bbj` (fsPath `c:/progs/x.bbj` on Linux) and round-trips through `URI.parse` unchanged.
- Langium's `EmptyFileSystem` `existsSync` always returns false, so tests must index every target that should resolve via `parse(..., { documentUri })`.
- tsconfig.json has `noUnusedLocals: true` and includes `src/**/*.ts` only.
- IntelliJ needs no change: `BbjLanguageServerFactory.createClientFeatures` overrides only the document-link feature (disabled) and completion, so LSP4IJ hover and definition stay enabled.
- Baselines: `npx tsc --noEmit` exits 0. `npx eslint` on bbj-validator.ts, bbj-hover.ts, bbj-definition-provider.ts, test/run-call-file-resolution.test.ts and test/definition.test.ts exits 0. run-call-file-resolution (6), definition (4) and hover (17) tests: 27 passed.

Scope:

- Untouched: USE `::file::` resolution in bbj-validator.ts `checkUsedClassExists` and bbj-scope.ts `getBBjClassesFromFile`. Their semantics differ (no empty-prefix filtering, index-only lookup), and merging them would change USE diagnostics.
