<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workspace `.vscode/settings.json` / IntelliJ settings → language server | `bbj.interop.host`/`port` arrive as untyped JSON through initialization options and configuration pushes |
| language server → java-interop socket | the validated host/port choose which peer the server connects to |
| rejected value → output channel | the warning echoes a value the workspace controls |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-110-01 | Tampering | `setConnectionConfig` (both entry points) | medium | mitigate | `validateInteropConfig` rejects empty/non-string hosts and non-integer or out-of-range ports per field; the setter calls it itself so no caller bypasses it (Tasks 1-2). |
| T-110-02 | Repudiation (log forging) | `formatInteropRejection` | low | mitigate | Strings are rendered with `JSON.stringify`, so a newline in a rejected host cannot forge a second log line. |
| T-110-03 | Denial of service | warning text | low | mitigate | The rendered rejected value is capped at 100 characters. |
| T-110-04 | Spoofing | a well-formed host that points at an attacker's peer | medium | accept | Validation is about shape (issues #509, #510); a valid value the user configured is honoured by design. Data from the peer is bounded in Phase 111. |
| T-110-SC | Tampering | package installs | low | accept | No package is installed. |
</threat_model>
