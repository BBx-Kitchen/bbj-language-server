<objective>
REF-06 (#606). A new vitest test compares the `bbj.compiler.*` settings that `package.json` contributes
to VS Code's Settings UI with the `COMPILER_OPTIONS` table that drives the compile QuickPick and the
bbjcpl arguments, in both directions: key set, type and default (D-05). The one setting that is not
a bbjcpl flag, `bbj.compiler.trigger`, sits in a named allow-list with its reason (D-07). Labels and
descriptions differ on purpose and are not compared (D-06). The test is the sync mechanism; no
generator is added (D-08).

Purpose: adding, removing or re-defaulting a compiler option on one side without the other today
desyncs the Settings UI from what the compile command does, and nothing notices.
Output: `test/compiler-options-package-json-drift.test.ts` and the phase's one-line `COVERAGE.md`.
No change to `package.json` or `compiler-options.ts` (measured while planning: 20/20 keys, 0 type
and 0 default differences).
