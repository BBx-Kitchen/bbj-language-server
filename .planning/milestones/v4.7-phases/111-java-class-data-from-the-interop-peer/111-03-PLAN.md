<objective>
Make Java documentation render literally in hover and completion: every peer- or javadoc-supplied
string is Markdown-escaped once, at the render boundary, and the fenced signature cannot break out of
its fence (issue #524; D-06, D-07, D-08, plus the D-02 bound on hover's fallback path).

Purpose: hover and completion hand Java javadoc to both IDEs as Markdown, so link or image syntax in it
renders as a clickable link or a remote image.
Output: `escapeMarkdown` and `toFenceSafeLine` in the shared module, escaped Java hover and completion
documentation, and `test/javadoc-markdown-escape.test.ts`.

User decision (2026-09-26, amends D-06): the less-than sign is NOT escaped. The installed javadoc corpus
has HTML tags in 3,081 of its 3,910 documented members (the a tag alone 4,473 times), and VS Code's hover
already strips raw HTML when supportHtml is off, so escaping it would only turn readable hovers into
literal tags. IntelliJ/LSP4IJ raw-HTML rendering stays unverified and is checked in UAT; if it renders an
HTML img tag, revisit (adding the less-than sign back to escapeMarkdown is the whole change).
</objective>
