<objective>
Keep the last check's compiler errors visible under on-save while the user types, on the lines
they belong to, until the next save replaces them (TRIG-04, D-01..D-04).

Purpose: today `composeWithVerdict()` drops a verdict's own diagnostics on the first keystroke
after it (research Pitfall 2). Under on-save no new verdict comes until the next save, so the
errors must be kept and re-placed. This plan takes CONTEXT's "mapping through content changes"
option: the text-document store records each incremental change the client sends, and a kept
diagnostic's line is mapped through those changes. A per-line text anchor cannot follow an error
whose own line the user edits, which D-01 requires.
Output: `bbj-kept-check.ts` (pure mapping, change log, recorder, kept-check store, composition),
the on-save branch in the validator, kept-check storing in the builder's verdict branch, and tests.
</objective>
