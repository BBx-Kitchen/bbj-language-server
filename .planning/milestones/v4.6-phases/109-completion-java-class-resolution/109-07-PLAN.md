<objective>
Close the one gap 109-VERIFICATION.md recorded against COMP-01 (ROADMAP criterion 1): a
fully-qualified reference to the class literally named `Class` (`java.lang.Class.` with no `USE`)
must offer static members only, like every other fully-qualified class reference, while the
`class` pseudo-member (`String.class.`, `java.lang.String.class.`, `obj!.class.`) keeps offering
java.lang.Class instance members. Per D-11, the fix is the class-reference detection in
`bbj-scope.ts`'s member-completion branch.

**Chosen approach: narrowing, not a documented limitation.** Today the MemberCall branch excludes
any receiver whose member text lowercased is `class`. The text cannot tell the two readings apart,
but the segment before it can. For the pseudo-member, that segment is a class or a value
(`String`, `java.lang.String`, `s!`, `java.lang.Class`). For a qualified reference to the class
named `Class`, it is a package (`java.lang`). The planner measured this signal against the
current tree (HEAD `571cafee`) with read-only probes, and with a temporary edit that was then
reverted. `this.typeInferer.getType(receiver.receiver)` is a `JavaPackage` for `java.lang.Class.`
and a `JavaClass` for all four pseudo-member shapes. No cyclic-link problem shows up: the
preceding segment's reference is already resolved, because resolving the receiver's own member
needed it. With the narrowed exclusion, `java.lang.Class.` gave `[class, forName()]`, equal to
the USE list. Every pseudo-member shape was unchanged, and all 9 existing tests in the file
passed. The verifier should therefore expect the gap closed by behaviour, not waived.

Purpose: ROADMAP criterion 1 is stated for any fully-qualified Java class. The class named `Class`
is its one reproduced counter-example.
Output: one narrowed condition and a rewritten comment in `bbj-scope.ts`, plus regression tests
in `test/completion-class-reference.test.ts`.
