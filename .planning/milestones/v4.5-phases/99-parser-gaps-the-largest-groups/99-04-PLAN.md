<objective>
Add an `IolistStatement` grammar rule so the `IOLIST` statement parses — standalone and behind a
label, with a long item list — and so variables that appear only inside one behave like variables
anywhere else.

Purpose: no grammar rule mentions this keyword at all today, so it lexes as a plain identifier, the
statement parses as a bare expression statement and the parser then has nowhere to put the following
comma. The fix is one new alternative in the `SingleStatement` alternation whose items are plain
expressions — the member-call rule's existing array-subscript postfix already covers an
all-elements item, so no dedicated item rule is needed (D-10). It runs last of the four groups
because every shape the group shows sits behind a label, and the label word only started working in
plan 03.

Output: the `IolistStatement` rule and its alternation entry, the regenerated parser, the fixture
`iolist-statement.bbj`, new cases in `parser-keyword-statements.test.ts`, and this group's
measurement section in `99-CONFORMANCE.md`.
</objective>
