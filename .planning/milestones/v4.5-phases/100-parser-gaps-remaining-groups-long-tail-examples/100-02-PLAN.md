<objective>
Let a semicolon-introduced comment follow a block boundary, and let class code carrying user line
numbers parse.

Purpose: two independent root causes behind about 8 of the 52 files on list A at the Phase 99 close.
The first: the generic statement chaining already lets a comment follow any ordinary statement, but
the five block-boundary markers are literals embedded in their own container rules and never reach
that mechanism — which is why a method-return statement's own comment tail works today and a method
end marker's does not. The second: the class member loop is a strict allow-list of members and
comments, while the top-level and method-body loops are permissive enough to swallow a bare line
number as its own throwaway statement; a number before a class member or before the class end marker
therefore breaks the whole class (criterion 2).

Output: the comment tail at the five boundaries, the line-number tolerance in the class member loop,
the regenerated parser, the fixtures `rem-after-block-boundaries.bbj` and `line-numbered-class.bbj`,
this group's cases in `parser-keyword-statements.test.ts`, and this group's run appended to
`100-CONFORMANCE.md`.
</objective>
