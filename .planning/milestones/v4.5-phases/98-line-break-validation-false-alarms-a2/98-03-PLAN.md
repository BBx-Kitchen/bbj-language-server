<objective>
Make the conflicting-`DECLARE` check and the two `METHODRET` checks agree with `bbjcpl` on code it
accepts, by narrowing them rather than removing them (16 A2 files: 7 conflicting DECLARE, 7 missing
METHODRET, 2 void-returns-a-value).

Purpose: all seven corpus DECLARE hits are program-level, and they fall into related types,
unresolvable types, a same short name from a different class, ordinary re-declaration per event
handler, and one deliberately contradictory pair. None of them is the thing the check was written
to catch. The two METHODRET checks disagree with the compiler in the same way, so they move in the
same stroke. One case stays an error on purpose: two declarations of one name inside a single
method body whose types both resolve and are unrelated — the single named exception the amended
success criterion 4 records (D-05, D-09).

Output: warning-severity METHODRET diagnostics, a scope-and-resolution-aware conflicting-DECLARE
check reusing the existing subtype logic, updated severity assertions in the two existing test
files, and a `declare-methodret.bbj` conformance fixture.

This plan touches no grammar and no lexer file, so it needs no `langium:generate` and is
file-disjoint from every other plan in its wave.
</objective>
