<objective>
Stand up the CONF-01 conformance-regression harness and prove it end-to-end on the largest A2
group — the `TABLE` statement (about 110 of 267 files).

This plan is the phase tracer: one thin path wired through every layer this phase touches
(new lexer terminal -> new grammar rule -> regenerated parser -> regression fixture -> a live
stricter test assertion), proven green before any other construct is attempted. Every later
plan drops its own regression file into the harness this plan builds and watches it go
red -> green.

Purpose: `TABLE` has no grammar rule at all today, so the keyword parses as a bare identifier
`ExpressionStatement` and the hex data behind it becomes one or more extra sibling statements on
the same line — which the generic standalone-statement mask correctly (by its own logic) reports
as "needs to start in a new line". The fix is at the root, in the grammar and lexer (D-01),
modelling `TABLE` as an opaque rest-of-line data token (D-03).

Output: `bbj-vscode/test/conformance-regressions.test.ts`, the
`bbj-vscode/test/test-data/conformance/` folder with `table-statement.bbj`, a `TABLE_DATA`
terminal, a `TableStatement` grammar rule, and new positive plus still-flagged cases in
`line-break-validation.test.ts`.
</objective>
