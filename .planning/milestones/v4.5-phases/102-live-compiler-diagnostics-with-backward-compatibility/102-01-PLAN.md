<assumption_delta_decision>
**Noun:** compiler diagnostic source — the value of a diagnostic's `source` field for a
compiler-produced syntax error, and by extension "which server capability is behind the socket".

Until this phase the language server had exactly one compiler diagnostic source (the save-time
`bbjcpl` run, `source: 'BBjCPL'`) and one server capability shape. Both monopolies end here: a
second compiler source appears, and the socket now answers to two server generations (one with the
endpoint, one without).

**Decision: add-alongside.** The save-time path keeps its source string, its merge helper and its
suppression rule byte-for-byte (D-03, D-09); the live path gets its own source string and its own
filter-then-append merge. Rationale: promoting the live source to "the" compiler source would mean
deciding now how it suppresses Langium's and `bbjcpl`'s diagnostics, which is exactly Phase 103's
requirement set (PSRV-06/07) and exactly the change the roadmap says can make diagnostics *worse*
for a user on an older BBj if it is unconditional.

**Accepted debt:** a line both sources complain about shows two diagnostics until Phase 103. The
forcing event for a promote is Phase 103's reconciliation, which keys on the source string this plan
introduces (which is why that string is rated costly, not reversible).

**Suggested, not required, invariant test:** every diagnostic this phase publishes carries a
`source` from a known two-value set, and the BBjCPL-suppresses-parse-errors rule fires for exactly
one of those two values.
</assumption_delta_decision>

<flagged_assumptions>
These are stated, not silently absorbed. Each is a defensible reading of a locked decision plus the
code as it is today; an executor that finds one wrong stops and reports rather than improvising.

1. **The mode line's visibility.** `logger.info` only emits when the log level is INFO or finer, and
   `main.ts` sets the level to WARN unless `bbj.debug` is true. D-07 says "one info line per
   connection", so the mode line is emitted with `logger.info` and is therefore visible in a
   default install only with `bbj.debug` enabled. The hand UAT in plan 04 turns `bbj.debug` on for
   that reason. Emitting the mode line at warn instead would make it noise on every connection, and
   no new setting or surface may be added (D-01, D-07).
2. **Live diagnostics inherit the save-time path's BBj-home gate.** `runBbjcplForDocuments` returns
   early when the `bbjcpl` binary is not found under the configured BBj home, and D-03 forbids
   changing that path in this phase. A user with no BBj home configured therefore gets neither
   source. This is accepted rather than routed around: the endpoint lives inside the same BBj
   installation, so a missing BBj home means a missing endpoint in practice.
3. **Probe-surfaced items dropped as routine or already-canon:** routine engineering prohibitions
   (no duplicated timer map, no `console.log` in place of the logger, no `any` in the new
   signatures) and canon security items (no `eval`, no credential handling) were surfaced by the
   prohibition recall and dropped deliberately — they are covered by the repository's lint and
   review conventions, not by this phase's acceptance criteria. Recorded so the drop is visible.
</flagged_assumptions>
