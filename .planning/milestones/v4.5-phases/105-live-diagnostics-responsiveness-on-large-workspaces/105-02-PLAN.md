<objective>
Build the pure snapshot composition that lets every writer of a document's diagnostics re-derive
the whole list from the same inputs.

The tracer: Langium's remembered list was validated on text version 1; the user has since edited
the file; BBj's verdict for the live version 2 arrives first. `composeWithVerdict`, fed the
remembered snapshot, the live text and the stored verdict, returns BBj's diagnostic plus Langium's
complaints treated by D-05. That one call runs through every layer this plan adds: the extended
snapshot store, the extended verdict record, the text-line lookup, the early reconciliation and the
case selection.

The expansion task pins every other case of the composition and the edge rows the spec-less probe
raised (empty inputs, line-text equality, idempotency).

Purpose: RESP-03's "latest text version wins, nothing lost, doubled or misattributed" is decided by
one pure function; plan 04 wires it into the validator and the builder.
Output: new exports in `bbj-diagnostic-reconciliation.ts` and their tests.

<decisions_resolved_here>
1. **Where the text version lives (Claude's discretion item 3, research Open Question 1):** the
   remembered Langium list's `WeakMap` value becomes `{ diagnostics, validatedText? }`, keyed by the
   `LangiumDocument` as today. The validated text (the CST root's full text, a reference to a string
   the parse result already holds, no copy) is compared with the live text rather than a version
   number, because an open document's `textDocument` is Langium's live, in-place-updated object: by
   validation time its version may already be newer than the text that was parsed.
2. **The verdict record** stays the uri-keyed `VerdictState` (it must forget on close), extended with
   optional `version` (the live editor version the verdict was computed for) and `diagnostics`
   (BBj's own list). "Current" means `version === liveVersion`.
3. **D-05 matching for a stale list:** a complaint's position is trusted only when the text of its
   start line is identical in the validated and the live text. The key recorded in `seen` uses the
   live line text, so the next keystroke's carry-over matches it exactly as Phase 103's does.
4. **`validatedText` absent** means "assume it is the live text". This keeps every existing caller
   and test that remembers a list without text on the Phase 103 path.
</decisions_resolved_here>

<flagged_assumptions>
1. **D-05's "matched by message and line text" for a stale list** is read as: the complaint's own
   message, and its start line's text unchanged at the same line number between the two texts. A
   complaint that only moved to another line is left as an Error until Langium re-validates (the
   next Langium validation fixes it; relocating stale ranges was not asked for).
2. Spec-less probe accounting for the whole phase is in plan 01's flagged assumptions.
</flagged_assumptions>
</objective>
