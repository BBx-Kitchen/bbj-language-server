<objective>
Wire the validator half: the carry-over that keeps a seen complaint yellow while the user types
(D-08), the close hook that forgets a document's verdict, and the line-break code that lets
reconciliation recognise line-break complaints without matching message text (D-04). Then prove the
whole thing end to end on real validator output, including the D-05 promise that linking
diagnostics come back once Langium's parse errors stand down.

Purpose: PSRV-07's promise has to hold between verdicts too — no red-yellow-red flicker on a line
the compiler already accepted — and it has to cover the line-break validator, the largest single
source of Langium-only false alarms in this milestone.
Output: a verdict-aware `validateDocument()`, an explicit `BBjDocumentValidator` constructor, tagged
line-break diagnostics, and `test/bbj-document-validator.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verdict state → per-keystroke validation | A decision the endpoint made about older text now changes how newer text is shown. |
| editor lifecycle → verdict state | Opening and closing documents in either IDE. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-103-09 | Tampering | carry-over matching | medium | mitigate | Too loose a match would show a new real error as a warning. The key is the exact message plus the exact text of the flagged line; anything unmatched stays an Error, and an edited-line test and an unseen-complaint test pin it. Task 1. |
| T-103-10 | Information Disclosure / Denial of Service | verdict state for closed documents | low | mitigate | Cleared on `onDidClose`, so state for a closed file never accumulates and never colours a reopened one. Task 1. |
| T-103-11 | Tampering | line-break messages | low | mitigate | Only a `data.code` is added; the six existing line-break and regression suites pin the messages and severities unchanged. Task 2. |
| T-103-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed in this plan or this phase. |
</threat_model>
