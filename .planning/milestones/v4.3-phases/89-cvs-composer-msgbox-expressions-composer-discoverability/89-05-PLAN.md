<objective>
Give VS Code users the CVS() composer (DISC-03, #649): a webview panel that composes a new `CVS(...)`
call or edits an existing literal-mask call in place, plus a command and a lightbulb.

It follows the addWindow and MSGBOX webview shape, with a lighter, flat layout (D-11), one shared `chars`
field that is disabled rather than hidden when irrelevant (D-12), and no version gating (D-13). Every mask
and statement comes from `cvsPreview` (plan 89-03).

`cvsPanelArgAt` is exported so the cue dispatcher (plan 89-09) opens the panel from a cue with exactly
the argument the lightbulb uses.

Purpose: DISC-03 in VS Code.
Output: `cvs-composer-webview.ts`, `cvs-composer-ui.ts`, activation wiring, and package.json contributions with tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview → extension host | Form values arrive as untrusted `postMessage` payloads |
| extension host → document | A composed call is inserted or replaces an existing span |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-89-15 | Tampering | an invalid preview written into the document | medium | mitigate | The extension recomputes `cvsPreview` on `insert` and refuses when `!valid`; the webview button is also disabled |
| T-89-16 | Tampering | an edit applied after the call text changed | medium | mitigate | `cvsCallStillMatches` compares the current span text to the captured `callText` immediately before the `WorkspaceEdit`; mismatch writes nothing |
| T-89-17 | Spoofing | document-derived text injected as markup in the webview | medium | mitigate | Nonce CSP as in the existing panels; every user-derived value is assigned via `textContent`, pinned by a source assertion |
| T-89-SC | Tampering | npm/pip/cargo installs | low | accept | No dependency is added |
</threat_model>
