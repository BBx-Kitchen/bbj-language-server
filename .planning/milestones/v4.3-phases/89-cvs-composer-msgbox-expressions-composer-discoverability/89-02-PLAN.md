<objective>
Make MSGBOX composable when its options argument is an expression (DISC-02, #648).
- A constant sum of integer literals and `BBjMsgBox.*` constants pre-fills the composer exactly like a
  literal (D-10).
- Anything else opens compose-and-replace mode. The original expression and an explicit replace banner
  are visible before Apply (D-08), with no extra confirmation dialog (D-09).

This ships before the MSGBOX cue is added (plan 89-09), so the cue never lands on an expression-valued
call that would silently open a compose-new composer. The decode moves into one shared function, and
both the language-server request and the VS Code lightbulb call it, so IntelliJ (plans 89-07, 89-08)
and VS Code decide identically.

Purpose: DISC-02 (#648).
Output: `decodeMsgboxCall` plus its recognizer and banner text, the request delegating to it, the VS Code
lightbulb offering replace mode, and the VS Code panel rendering the banner.
</objective>

## Flagged assumptions

- **Unresolved probe row (DISC-02, unclassified):** the edge probe could not classify DISC-02's text.
  This plan assumes "a sum of constant Java static fields" means the closed `BBjMsgBox.*` set already
  catalogued in `msgbox-composer.ts` (RESEARCH.md Assumption A2). A static field of any other class
  (for example `SomeClass.FLAG`) is treated as undecodable and opens compose-and-replace mode. No
  java-interop evaluation is attempted (the CONTEXT.md deferred list excludes general expression
  evaluation). This stays flagged for the verifier and the user.
- A constant sum whose value carries bits outside the MSGBOX masks decodes exactly as an integer literal
  of the same value does today. This plan does not change that pre-existing integer-literal behaviour.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| document text → options recognizer | Arbitrary user-written expression text is classified |
| decode result → webview | The original expression text is rendered inside a webview |
| composer Apply → document | A compose-and-replace write overwrites the options expression |
