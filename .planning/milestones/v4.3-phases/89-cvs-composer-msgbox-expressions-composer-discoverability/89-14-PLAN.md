<objective>
Close UAT gap G-89-3 on the shared language server and in VS Code (DISC-03, #649).

Today an unfinished CVS call is decoded as found but not editable, with the missing-mask reason and no prefill. That covers `a$ = CVS(`, `CVS()`, `CVS(a$`, `CVS(a$,` and `CVS(a$)`. The result:
- IntelliJ shows an error instead of opening the composer.
- The VS Code lightbulb silently offers nothing.
- The VS Code command inserts a whole call inside the partial one.

This plan:
- gives such a call its own composable decode outcome (`incomplete`), carrying the call span and a prefill;
- makes the VS Code lightbulb, panel and command compose into that span, through the existing `cvsCallStillMatches` stale-edit check, now made span-exact;
- pins that half-typed lines stay cue-free.

Plan 89-15 builds the IntelliJ half in parallel against the same wire field. Plan 89-16 proves both installed bundles and stages the human re-run.

Purpose: an unfinished `CVS(` becomes a composer entry point in every IDE, and never a nested call.
Output: the `incomplete` outcome in `cvs-composer.ts`, the complete-the-call mode in the VS Code UI, and unit tests.
</objective>

## Gap decisions (recorded for G-89-3)

The UAT gap left these decisions to the planner. They are binding for plans 89-14, 89-15 and 89-16.

1. **Shape of the composable outcome.** The new outcome is `incomplete: true` on `CvsDecodeCallResult`, with `found: true`, `editable: false`, no `reason`, and `edit`/`initial`/`trailingArgs` present.
   - `editable` stays false, so any consumer that does not read the new flag keeps refusing to rewrite the call (fail closed).
   - The cue's existing `found && editable` gate needs no change.
   - The `missing-mask` reason is retired because nothing produces it any more. `non-literal-mask` and `unknown-bits` stay hard stops (D-14).
2. **The closed call `CVS(a$)` joins the outcome.** IntelliJ auto-inserts the closing parenthesis, so typing `CVS(` then `a$` produces exactly the closed `CVS(a$)`. A CVS call without a mask is also already a builtin arity error (`conversion_flags:int` is required in `functions.ts`), so composing into it cannot discard complete user logic. `CVS(a$, )` (an empty mask) joins for the same reason.
3. **Text after the mask position is preserved.** The gap text suggested "empty chars". This plan instead:
   - prefills `chars` from a third argument that is not `ERR=`;
   - carries `ERR=` arguments as `trailingArgs`;
   - reuses the editable branch's own split to do both.

   Replacing the span must never silently drop typed text, for example in `CVS(a$, , ERR=100)`.
4. **No cue on half-typed lines.** A lens that appears above the line while the user types `CVS(`, and vanishes or changes once the mask becomes a literal, shifts the editor content in the middle of typing. That is the disruption UAT test 4 (no typing lag) guards against. D-06's "every eligible line" keeps meaning a call the composer can pre-fill from. Unfinished calls are reached through the caret entry points: Alt+Enter, the lightbulb, the context menu and the palette.
5. **`bbj.composeCvs` becomes position-aware.** In IntelliJ, the context-menu action and Alt+Enter already share one position-aware launcher. The VS Code command inserted a whole call at the cursor, even inside a partial or existing call — the nesting this gap forbids. Without a panel argument it now decodes the cursor first.
6. **IntelliJ keeps one guarded CVS write.** Completion reuses the existing `applyIfUnchanged(` body in `openCvs`, with `sameCvs` and the re-issued `cvsDecodeCall`. The counts pinned in `ComposerApplyGuardSourceGuardTest` (6 / 6 / 1 / 2) therefore stay the same by design. That test is updated deliberately with an `openCvs`-scoped assertion rather than a count bump, because a second CVS write site would only duplicate the guard wiring (plan 89-15).
7. **The MSGBOX( nesting is not in this plan set.** On `x = MSGBOX(` the MSGBOX composer already opens (the decode says `found: false` and compose-new runs), so no action is blocked. The defect there is a latent write-shape corruption. MSGBOX's decode also carries its own `replace` payload, `sameMsgbox` and banner semantics, so it needs its own design. The work belongs to Phase 90 (Composer Robustness), which is where CONTEXT's Deferred Ideas already send composer robustness fixes. Plan 89-16 records it as a pending todo.
8. **`ConfigureCvsIntention.isAvailable` stays a text check.** No LSP round trip can run inside `isAvailable`. Once the unfinished call is composable, the text heuristic no longer offers an intention that is guaranteed to fail.
