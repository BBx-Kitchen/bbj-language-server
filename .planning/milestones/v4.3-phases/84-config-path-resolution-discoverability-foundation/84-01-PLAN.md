<objective>
Establish the one shared answer to "which file is the BBj config file", computed once in the
language server and readable by both IDE hosts two ways: an on-demand `bbj/resolvedConfigPath`
request and a server-pushed notification of the same shape.

Purpose: ROADMAP criterion 4 — both hosts must agree on the same resolved path even when only a
BBj-home setting is configured, because the fallback logic is exposed from one shared source
rather than reimplemented per host. Everything else in Phase 84 consumes this contract.
Output: `config-path-resolver.ts` (pure resolution + comparison), `resolved-config-path-request.ts`
(the custom request), a `notifyResolvedConfigPath` push, and `BBjWorkspaceManager.getResolvedConfigPath()`.
</objective>

<assumption_delta_decision>
Noun now primary: **the resolved config path** (one canonical string), not the raw `bbj.configPath`
setting. The assumption-delta scan flagged `pluralization` on "fallback" and `chosen` on "custom" —
what used to be a single implicit derivation buried in `initializeWorkspace` becomes a named,
first-class value with an explicit `source` discriminator.

Decision: **promote**. `ResolvedConfigPath` is the primary representation everywhere downstream;
the raw setting is demoted to an input of `resolveConfigPath()`. No consumer in this phase reads
`bbj.configPath` to derive a path — only to feed the resolver (or, on a host, as the D-02
pre-answer stand-in, which is the explicit setting verbatim and never a derivation).

Invariant test encoding this: `resolveConfigPath` is the only function in the repository that
concatenates a BBj home with `cfg` and `config.bbx`; the plan's prohibition test asserts that.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IDE settings → language server | `initializationOptions.configPath` / `didChangeConfiguration` carry an arbitrary user-supplied string into path resolution |
| language server → IDE client | the pushed `bbj/resolvedConfigPath` notification crosses the LSP wire into both hosts |
| resolved path → spawned BBj process | the same string later becomes a `-c` argv element on both hosts (consumed in plans 84-03 and 84-06) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-84-01 | Tampering | `config-path-resolver.ts` path handling | medium | mitigate | Reject non-absolute input outright; expand only a leading tilde; canonicalize through `path.normalize` plus `fs.realpathSync.native` so parent-directory segments and symlinks collapse before any consumer builds argv from the string |
