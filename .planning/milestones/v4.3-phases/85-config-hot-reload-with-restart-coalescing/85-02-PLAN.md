<settled_facts>
Research is disabled for this project; these were settled by reading the installed Langium 4.x sources and are not open questions.

- **Langium's in-flight-build signal.** `DefaultDocumentBuilder` (`node_modules/langium/lib/workspace/document-builder.js`) keeps `protected currentState: DocumentState`. It is set to `DocumentState.Changed` (0) at the top of both `build()` and `update()`, and `runCancelable` sets `currentState = targetState` after each phase, ending at `DocumentState.Validated` (6). So `currentState < DocumentState.Validated` is exactly "a build is in flight or has never completed". `waitUntil(state)` resolves immediately when `currentState >= state`, confirming the same semantics. `currentState` is `protected`, so `BBjDocumentBuilder` — which is the registered shared `DocumentBuilder` (`bbj-module.ts:170`) — can read it directly; no reflection and no new bookkeeping flag is needed.
- **`build([], {})` walks `currentState` to Validated** even for an empty document list, because `runCancelable` assigns `currentState` unconditionally. That is what makes the predicate testable against hermetic `EmptyFileSystem` services without building any real document.
- **BBjCPL pending work** is exactly `cplDebounceTimers.size > 0` in `bbj-document-builder.ts` (the 500 ms `SAVE_DEBOUNCE_MS` map).
</settled_facts>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| language server internals → IDE host | The quiescence gate decides *when* a restart request crosses the LSP connection. |
| IDE settings push → language server | `onDidChangeConfiguration` re-resolves the config path and re-arms a filesystem watch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-85-03 | Denial of Service | the bounded quiescence wait in `config-watcher.ts` | medium | mitigate | `QUIESCENCE_TIMEOUT_MS = 5000` caps the wait; at most one wait is outstanding (cancel-then-schedule on a single timer handle); `dispose()` clears it. A busy workspace cannot starve the reload and a wait cannot accumulate. |
| T-85-09 | Denial of Service | repeated `bbj.configPath` settings pushes re-arming the watch | medium | mitigate | `updateResolvedPath` closes the previous handle before arming, dedupes arm-failure warnings per path, and is a no-op before `start()`; a settings-change storm produces at most one outstanding quiescence wait. |
| T-85-10 | Tampering | a settings-supplied config path pointing at an attacker-writable directory | low | accept | The path is already resolved and trusted by Phase 84's `resolveConfigPath`; this plan only watches the directory that resolution already named. No new trust is extended and no content is executed. |
| T-85-11 | Denial of Service | `hasPendingWork()` reading `currentState` on a hot path | low | accept | The predicate is two field reads and a map-size read, polled at most every 100 ms and only while a reload is pending. |
| T-85-SC | Tampering | npm/pip/cargo installs | low | accept | This plan adds no package-manager install task and no new dependency; the package-legitimacy gate has nothing to audit. |
</threat_model>
