<objective>
Stop VS Code composer panels from leaking their message-handler listeners across repeated open and close (DISC-09, #530) — for all six composer panels, not only the four named in the issue.

This plan:
- adds one shared helper that ties a panel's message-handler subscription to that panel's own `onDidDispose`;
- routes all six panels through it;
- adds a regression test that discovers panel modules from the source tree and proves an open-then-dispose cycle leaves the extension context unchanged and the handler disposed.

Purpose: a long VS Code session with heavy composer use no longer accumulates dead listeners on the extension context.
Output: the helper, six rewired panels, a discovery-based lifecycle test, and updated test fakes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| panel lifetime → extension context lifetime | A per-panel resource registered on the extension-wide context outlives the panel |
| webview → extension message channel | Messages arrive only while a subscription exists |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
