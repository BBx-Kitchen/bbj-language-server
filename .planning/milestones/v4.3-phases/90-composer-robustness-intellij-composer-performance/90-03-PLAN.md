<objective>
Make a second composer open in the same IntelliJ session pay no server-resolution or catalog round trip, while never reusing a handle across a language-server restart (DISC-11, #612).

This plan:
- adds a plain-Java `ComposerHandleCache` holding the resolved server proxy and the catalogs, with identity-checked invalidation;
- converts `BbjComposerService` into a project service that owns one cache and clears it on every server status change;
- routes `ComposerFlow.launch` through the cache for both the proxy and the catalogs, and clears the cache on any launch failure so the balloon Retry resolves from scratch;
- keeps the static `server(project)` facade, so `BbjCompileAction` and `BbjRefreshJavaClassesAction` use the cache with no edit.

Purpose: repeated composer use feels instant, and a restarted server is never addressed through a stale proxy.
Output: the cache seam, the service and flow wiring, and plain JUnit behaviour and source-guard coverage.
</objective>
