<objective>
Make the three remaining IntelliJ composer dialogs send one preview round trip per settle point instead of one per keystroke (DISC-10, #611), using the existing `Scheduler`/`AlarmScheduler`/`PreviewDebouncer` seam.

This plan:
- ports the `SetoptsComposerDialog` debounce shape to `MsgboxComposerDialog`, `AddWindowComposerDialog` and `AddChildWindowComposerDialog`;
- moves those dialogs into the source guard's debounced subject list and pins that all six dialogs share one seam with the same delay;
- adds the millisecond boundary test at the dialog delay under `ManualScheduler`.

Purpose: fast typing in a composer no longer floods the language server, and OK can never accept a stale statement.
Output: three debounced dialogs, a stronger source guard, and a boundary test.
</objective>
