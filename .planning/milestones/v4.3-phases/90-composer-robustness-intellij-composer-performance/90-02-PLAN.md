<objective>
Reject malformed free text in the addWindow and addChildWindow composers before the insert is applied (DISC-07, #623). Validity travels in the shared preview payload, so VS Code and IntelliJ gate the same way.

This plan:
- adds per-field error strings and a `valid` flag to `addwindowPreview` and `addchildwindowPreview`, using the existing MSGBOX validators and one new numeric-field rule;
- renders each error under its field in both webviews, marks the input invalid and disables Insert;
- keeps an extension-side `if (!r.valid) break;` guard, so a forced Insert is refused.

Purpose: a typo such as `"10"` in a geometry field or `caption` as a title can never be written verbatim into the user's BBj source.
Output: validated preview payloads, updated panels, and tests at the pure, pass-through and panel levels.
</objective>
