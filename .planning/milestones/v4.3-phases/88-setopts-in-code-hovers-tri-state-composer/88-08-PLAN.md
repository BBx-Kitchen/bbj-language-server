This plan therefore does three things, in dependency order:

1. Removes the mechanism. `vscode:prepublish` today runs `shx cp ../LICENSE ./LICENSE`,
   `esbuild-base --minify` and `lint`. `esbuild-base` writes `out/main.js` from
   `src/extension.ts` — but `package.json`'s `main` is `./out/extension.cjs`, and the language
   server is `out/language/main.cjs`. Both are produced only by `npm run build` (`tsc -b` plus
   `esbuild.mjs`), which `vsce package` never invokes. So `vsce package` — including the one
   inside `bbj-ext-install` — happily packages whatever `out/` happened to contain. That is the
   mechanism that shipped a pre-Phase-88 bundle into the UAT round.

2. Proves the fix behaviourally, not by grep. A new functional test resolves the install VS Code
   actually loads from `extensions.json`, spawns that bundle's `out/language/main.cjs` as a real
   `--node-ipc` LSP server (the same invocation `extension.ts` uses, per
   `test/language-server-lifecycle.test.ts`), opens the user's exact reported reproduction, and
   asserts real hover markdown and real `bbj/composer/setopts/*` responses come back. A grep
   proves a symbol name survived bundling; an LSP round-trip proves the shipped server computes
   the answer.

3. Tests the one hypothesis nobody has tested. `g-88-2-composer-never-activates.md` eliminated a
   hang bug in the IntelliJ intention's own code and eliminated a standing LSP4IJ platform
   defect, but left exactly one alternative alive: "a slow or blocked BBjCPL compile-diagnostics
   round trip triggered by the file's content", which Phase 82's diagnostics-free UAT never
   exercised. IntelliJ's Alt+Enter action search collects LSP4IJ quick fixes via
   `textDocument/codeAction` and waits on diagnostics — both served by the SAME shared language
   server this harness now drives. Measuring them on the user's exact snippet either produces
   real evidence of a slow path or eliminates the last alternative, moving IntelliJ's diagnosis
   from "strongly corroborated" toward proven, before a human ever opens an IDE.
